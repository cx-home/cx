# `cx-stdlib/i18n` — message catalogs, translation, ICU MessageFormat

```cx
[module-meta name=i18n tier=A status=current
```

**Status:** Current

Normative reference for the `cx-stdlib/i18n` sub-package: function-level surface and supported ICU MessageFormat grammar.

---

## §1. Scope

`cx-stdlib/i18n` is the message / translation layer of CX's internationalization surface — sibling to [`cx-stdlib/locale`](locale.md) primitives:

- **Message catalogs** — a tagged `[catalog …]` element mapping `key` to per-locale MessageFormat strings; built from a map or loaded from disk; merged and inspected.
- **Message resolution** — resolve a key for a target locale through a locale-fallback chain, then evaluate the resolved MessageFormat string against an args map.
- **Direct MessageFormat** — evaluate a MessageFormat string with no catalog.
- **Full ICU MessageFormat** — interpolation, plural (CLDR rules), select, selectordinal, nested forms, typed args (number / date / time / currency) delegated to `cx-stdlib/locale`.
- **CLDR plural data** — the locale's plural category for a number.

Boundary rule:

> **Selects / interpolates / pluralizes a translated message? → `i18n`. Locale-aware primitive format of a single value (number / date / currency / collation / case)? → `locale`.**

`i18n` depends one-way on `locale`. It carries no number/date/currency formatter and no locale-data resolver — it delegates all of that to `locale`. Locale arguments are BCP 47 tags.

## §2. Conceptual model

### §2.1. Catalog

A **catalog** is a tagged `[catalog …]` element:

```
key → { locale → MessageFormat-string }
```

Tagged structural values (catalogs included) are elements; flat data records are maps. The in-memory shape:

```cx
[catalog default=<default-locale>
  [entry key=<key>
    [msg locale=<locale> <messageformat-string>]
    ...]
  ...]
```

The `default` attribute is the default-locale fallback (`"en"` if absent). Each `[entry key=K …]` child maps a message key to its per-locale `[msg locale=L "…"]` children.

Catalogs are immutable values. Functions taking a catalog validate the argument is a `[catalog …]` element; a non-catalog value raises `CXER3805 E_I18N_NOT_A_CATALOG`.

### §2.2. Locale-fallback chain

Message resolution falls through a chain, returning the first entry that exists:

```
es-MX  →  es  →  en  →  default-locale
```

Full tag, then progressively-truncated tags (region dropped, then script), then `"en"`, then the catalog's declared default. Truncation semantics reuse [`cx-stdlib/locale`](locale.md)'s language/region fallback.

### §2.3. MessageFormat

ICU-MessageFormat-syntax template. Literal text passes through; `{…}` forms evaluate against the args map. Grammar in §3.4.

### §2.4. Locale-data resolution

CLDR plural data and typed-arg locale data are resolved through `cx-stdlib/locale`'s data-resolution order (explicit override `CX_LOCALE_DIR`, then system data, then bundled snapshot). There is one locale-data resolver in the stdlib, owned by `locale`.

## §3. Public function surface

### §3.1. Catalogs

```
[?def catalog-from-map scope=public pure   [returns element] ($m::map) ...]
[?def load-catalog     scope=public impure [returns element] ($path::string) ...]
[?def catalog-merge    scope=public pure   [returns element] (*$catalogs::element) ...]
[?def catalog-merge-seq scope=public pure  [returns element] ($catalogs::[sequence element]) ...]
[?def catalog-locales  scope=public pure   [returns [sequence string]] ($catalog::element) ...]
[?def catalog-keys     scope=public pure   [returns [sequence string]] ($catalog::element) ...]
```

`catalog-from-map` builds a `[catalog …]` from a map of shape `{ key → { locale → msgformat } }`. The optional `"default"` map entry sets the catalog's default locale (`"en"` if absent). This setter key is the string `"default"` — not the atom `:default` — consistent with the string-keyed convention of every other key in the input map.

`load-catalog` reads the canonical on-disk CX-document form:

```cx
[catalog default=en
  [entry key="inbox.unread-count"
    [msg locale=en "{n, plural, one {# unread message} other {# unread messages}}"]
    [msg locale=ru "{n, plural, one {# непрочитанное} few {# непрочитанных} many {# непрочитанных} other {# непрочитанного}}"]]
  [entry key="greeting"
    [msg locale=en "Hello, {name}!"]
    [msg locale=fr "Bonjour, {name} !"]]]
```

The on-disk form is the in-memory shape; round-trip is byte-identical. A malformed MessageFormat string at load raises `CXER3800 E_I18N_MESSAGEFORMAT_INVALID`.

`catalog-merge` is variadic, left-to-right, last-writer-wins; the result's `default` is the last catalog's if it declares one, walking right-to-left otherwise. Merging zero catalogs returns `[catalog default="en"]`. `catalog-merge-seq` is the programmatic companion for a runtime-assembled list.

### §3.2. Message resolution

```
[?def message    scope=public pure [returns string] ($catalog::element $key::string $locale::string $args::map) ...]
[?def message-or scope=public pure [returns string] ($catalog::element $key::string $locale::string $args::map $fallback::string) ...]
```

`message` resolves `key` for `locale` via §2.2, then evaluates the resolved string against `args`. Strict: an unknown key raises `CXER3801 E_I18N_KEY_NOT_FOUND`. A MessageFormat string referencing an absent arg raises `CXER3802 E_I18N_MISSING_ARG`.

```cx
[$i18n:message $catalog "inbox.unread-count" "ru" {n=5}]
  ; → "5 непрочитанных"
[$i18n:message $catalog "greeting" "fr-CA" {name="Marie"}]
  ; → "Bonjour, Marie !"   (fr-CA → fr)
```

`message-or` returns `fallback` (itself evaluated as a MessageFormat string against `args`) instead of raising `CXER3801` on missing key. Missing args still raise `CXER3802`.

### §3.3. Direct MessageFormat

```
[?def format-message scope=public pure [returns string] ($msgformat::string $locale::string $args::map) ...]
```

```cx
[$i18n:format-message "{count, plural, =0 {no items} one {# item} other {# items}}" "en" {count=0}]
  ; → "no items"
```

### §3.4. Supported ICU MessageFormat grammar

`'` quotes a literal `{`, `}`, or `#`; `''` is a literal apostrophe.

**Interpolation** — `{name}` substitutes `args["name"]` string-coerced via the target locale:

```
"Total: {n}"   {n=1234567}  en  → "Total: 1,234,567"
```

**Plural** — `{argname, plural, …branches…}` selects by CLDR plural category. `#` is the locale-formatted number. Exact `=N` matches take priority over category branches. Categories: `zero` / `one` / `two` / `few` / `many` / `other` (only those a locale uses appear; `other` is required). `offset:N` prefix subtracts N from the value used for `#` and category selection.

**Select** — exact-string match against branch keywords with required `other` catch-all.

**SelectOrdinal** — selects by CLDR ordinal plural rules (distinct from cardinal):

```
"{place, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}"
  {place=1}  → "1st"   {place=2} → "2nd"   {place=11} → "11th"
```

**Nested** — `plural` / `select` / `selectordinal` branches may contain further `{…}` forms to arbitrary depth.

**Typed args** — `{argname, type, style}` delegates to [`cx-stdlib/locale`](locale.md):

| Form | Delegates to |
|---|---|
| `{n, number}` | `[$locale:format-number]` |
| `{n, number, percent}` | `[$locale:format-number-with-opts]` (`style="percent"`) |
| `{p, number, currency}` | `[$locale:format-currency]` |
| `{d, date, short\|medium\|long\|full}` | `[$locale:format-date-style]` |
| `{t, time, short\|medium\|long\|full}` | `[$locale:format-datetime]` |

Inline ICU number-skeleton syntax is not currently supported; named styles only.

### §3.5. CLDR plural data

```
[?def plural-category         scope=public pure [returns atom] ($n::number $locale::string) ...]
[?def plural-category-ordinal scope=public pure [returns atom] ($n::number $locale::string) ...]
```

Return the cardinal / ordinal CLDR plural category as one of `:zero` / `:one` / `:two` / `:few` / `:many` / `:other`. If CLDR data for `locale` is unavailable, both **fail soft**: return `:other` and emit a diagnostic rather than raise (§4).

```cx
[$i18n:plural-category 1  "en"]   ; :one
[$i18n:plural-category 2  "ru"]   ; :few
[$i18n:plural-category 5  "ru"]   ; :many
[$i18n:plural-category 0  "ar"]   ; :zero
```

## §4. Edge cases and policy

`i18n` is **strict-by-default** like the rest of the stdlib except in one case: missing CLDR plural-rule data degrades to `:other` and emits a diagnostic rather than raising. Because `i18n` renders user-facing message strings, a slightly-off plural beats a crashed render. Every other condition (malformed MessageFormat, unknown strict key, missing arg, type mismatch, not-a-catalog) still raises.

For `"zh-Hant-TW"` the chain is `zh-Hant-TW → zh-Hant → zh → en → default-locale`. Script is dropped after region.

A `plural` / `selectordinal` form must include `other`; `select` must include `other`. Omitting `other` raises `CXER3800` at parse time.

CLDR plural categories differ sharply across languages: English uses `one` / `other`; Arabic uses all six; Russian and Polish key on last digit and last-two-digits. The `{n, plural, …}` branch implements the CLDR rule for the locale.

Bare `{name}` interpolation coerces: number → `[$locale:format-number]`; date / datetime → `[$locale:format-date]` default style; string verbatim; atom → its name; bool → `"true"` / `"false"`. Use a typed form to control formatting.

Every numeric / date / currency rendering — the `#` plural-number substitution, bare `{n}` interpolation, and all typed-arg forms — is produced by calling `cx-stdlib/locale`. `i18n` ships no independent formatter.

## §5. Error codes

| Code | Mnemonic | Raised by |
|---|---|---|
| `CXER3800` | `E_I18N_MESSAGEFORMAT_INVALID` | Malformed MessageFormat string (unbalanced `{}`, bad type keyword, `plural` / `select` missing required `other`, malformed `=N` / `offset:`) — at `load-catalog` / `format-message` parse |
| `CXER3801` | `E_I18N_KEY_NOT_FOUND` | `message` (strict) on a key absent at every level of the fallback chain |
| `CXER3802` | `E_I18N_MISSING_ARG` | A MessageFormat string references an arg name absent from `args` |
| `CXER3803` | `E_I18N_ARG_TYPE_MISMATCH` | A `plural` / `selectordinal` arg is non-numeric, or a typed `number` / `date` arg cannot be coerced |
| `CXER3804` | `E_I18N_PLURAL_DATA_UNAVAILABLE` | Retired as a hard-raise. Repurposed as the non-fatal diagnostic identifier carried by the emitted `[$log:warn]` record when CLDR plural data is unavailable; never raised |
| `CXER3805` | `E_I18N_NOT_A_CATALOG` | A function expecting a `[catalog …]` element was passed a non-catalog value |

## §6. Conformance fixtures

Under `conformance/stdlib/i18n.cxd`:

- Interpolation: `"Hello, {name}!"` with `{name="Ada"}` → `"Hello, Ada!"`; numeric: `"Total: {n}"` `{n=1234567}` `en` → `"Total: 1,234,567"`.
- CLDR plural — en: `one` (n=1) vs `other` (n=0,2,5).
- CLDR plural — ar: all six categories for representative `n`.
- CLDR plural — ru: 1 → one, 2 → few, 5 → many, 21 → one, 12 → many.
- CLDR plural — pl: 1 → one, 2 → few, 5 → many, 22 → few.
- Exact `=N` priority: `{n, plural, =0 {none} one {# item} other {# items}}` `{n=0}` → `"none"`.
- Select: `{gender, select, male {He} female {She} other {They}}` per keyword + unmatched → `other`.
- SelectOrdinal — en: 1 → "1st", 2 → "2nd", 3 → "3rd", 4 → "4th", 11/12/13 → "11th/12th/13th".
- Nested: plural inside select produces correct branch × category × `#`.
- Fallback chain: `es-MX → es → en`; unknown key raises `CXER3801` under `message`; returns default under `message-or`.
- Catalog shape: `catalog-from-map` / `load-catalog` return `[catalog default=… [entry …] …]`; on-disk form round-trips byte-identically.
- Variadic merge — last-writer-wins; `catalog-merge-seq` matches `catalog-merge`.
- Not-a-catalog: passing a non-catalog raises `CXER3805`.
- Missing plural data degrades: `plural-category` / `plural-category-ordinal` return `:other` and emit the `CXER3804` diagnostic; `{n, plural, …}` selects `other`.
- Typed-arg delegation: `{p, number, currency}` / `{n, number}` / `{d, date, long}` render byte-identical to the corresponding `cx-stdlib/locale` call.
- Missing arg raises `CXER3802`; unbalanced `{}` and `plural` without `other` raise `CXER3800`.

## §7. Capabilities

Effectful functions in `cx-stdlib/i18n` run under deny-by-default capabilities ([`spec/core/security.md`](../core/security.md) §2): the effect point checks the active set and raises `cx-err:CXER0271` (E_CAP_DENIED, naming the missing capability and resource) when the grant is absent. Pure functions (in-memory transforms, parsing, formatting) require no capability.

Only catalog loading touches the filesystem and requires `read`. Message lookup and formatting over an already-loaded catalog are pure.

| Capability | Functions |
|---|---|
| `read` | `load-catalog` |
| (none) | all message lookup and formatting over already-loaded catalogs |
