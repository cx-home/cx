# RULED: 1384-a, 1391-a — `cx fmt` enforces its own §1 contract with a second guard, fixes the two text-run/char-ref defects at the cause, formats a bracketed or collection value in argument and attribute position, and never declines silently again

Integrator, 2026-09-12, under the owner's delegation. Both issues were pulled into v0.18 the same
day (INT-2). Measured against `origin/release/0.18` @ `58bb2eebc`.

## Why the two ride together

They are the two halves of one sentence. `formatting.md` §1 says a formatter "never changes the
data or the node tree — same tree in, same tree out", and §7 (a) makes that a conformance
obligation: "output re-parses to a tree equal to the input tree". #1384 is that sentence being
BROKEN at exit 0 — a text run beside a character reference gains a space or splits into two
nodes. #1391 is the same entry point declining to do anything at all, also at exit 0, on 36% of
the tracked corpus. One is a silent change, the other a silent refusal, and both are silent
because `fmt_source_lane` has exactly one exit that says nothing either way. The fix for each is
the other's precondition: a guard that fails closed is only tolerable if a decline is loud, and a
decline is only loud if the lane can tell a real refusal from a no-op it never noticed.

## RULED: 1384-a — the contract is ENFORCED, and the two measured defects are fixed at the cause

The formatter's contract gets a second guard, beside #1330's idempotence guard and at the same
single public entry (`fmt_source`):

- after formatting, the output is RE-PARSED and its node tree compared to the input's — node
  kinds, order, text values after entity decoding, attributes;
- on any difference `cx fmt` FAILS CLOSED **LOUDLY**: the source is handed back unchanged, one
  stderr line names the first differing node path and both values, exit 1, with a code in fmt's
  own CXER band;
- the band is registered in `governance.md` §9.6 before it is used (the registry is
  append-only and allocation-precedes-emission).

AND the two measured defects are fixed AT THE CAUSE, not merely caught by the guard: `[p ab:c
&#169;]` and `[p abc. &#169;]` round-trip byte-for-byte through `cx fmt` — same value, same node
count. A guard alone would turn a data-corrupting format into a refusal to format; the issue is
about the corruption, and the fix is that the two shapes format correctly.

Ring 0 — `vcx/cx/program_fmt.v` and the formatter it fronts.

**On the comparison, because this is the axis the issue's own proposed-ruling comment got wrong.**
The comparison is of the TREE, not of the canonical data TEXT. Worker A's measurement on #1384
("corpus=152, new-differs-from-parent=70, in all 70 `cx fmt` becomes a no-op") was taken with a
canonical-data-TEXT oracle, which is strictly stronger than §1 asks for: it makes `'s'` differ
from `s` and `1_000` differ from `1000`, neither of which is a difference in the tree. §1's
subject is the node tree, so the guard's subject is the node tree; scalar spelling, quoting and
layout are exactly the presentation axes §2 grants the formatter. `conformance/fmt.cxd`'s runner
has asserted this same property per case since the suite was authored (assertion 2 of 3,
`cx_text_canonical(fmt(in)) == cx_text_canonical(in)`) and all 44 cases satisfy it — so the
property is already gate-enforced on the corpus and is merely missing at the entry point the LSP
calls. Worker A's other measurement stands and is the reason this needs no letters: swept over
all 44 cases, the number whose data reading changes under `cx fmt` today is ZERO.

**Grading.** Corpus first: the two repros are fixtures in `conformance/fmt.cxd` with their output
pinned. The guard's REFUSAL cannot be authored from the outside — once the causes are fixed there
is no input that trips it, and an input that tripped it would be a second open defect — so the
guard is graded with a V unit test that feeds a forged mismatch directly to the comparison.

## RULED: 1391-a — argument and attribute position format, and a decline is never silent

A bracketed or collection value in ARGUMENT or ATTRIBUTE position — operator call, `$` call,
directive, map literal, sequence literal, nested element; the boundary table in the issue — IS
formatted, under the same layout rules the formatter already applies to those constructs in item
position. `[x total=[* 2 3]]` formats for the same reason `[x [* 2 3]]` does; position is not a
formatting axis.

A DECLINE anywhere in the lane is no longer silent. `cx fmt` writes one stderr line naming the
construct and its position and exits 1. The source is still handed back unchanged — fail-CLOSED
is unchanged; what changes is that it is fail-closed and SAID. (`cx fmt` has no `--check` flag
today — `--check` is `cx lock`'s — so there is one exit path to make loud, and inventing a second
surface is outside this decision.)

The `fmt-sweep-gate` ratchet `FMT_SWEEP_MAX_DECLINED` comes down to the newly measured count, by
the issue's own perturbation method, and each remaining declined file is listed in the ratchet's
log with the construct that declined it — a count with no names is what let one hole read as 93
stubborn legacy files.

**Grading.** Corpus first: one fixture per row of the issue's boundary table, formatted output
pinned, authored before the code.

## What neither decision touches

- `cx --cx` (the default, non-`--lossless` data emitter) is separately wrong on `[p ab:c &#169;]`
  — one Text node becomes three scalars, one of them an atom. That is a different emitter with a
  different audience, it is measured on #1384 and left there, and nothing in this work changes it.
- The §2/§3 profile MODEL. The shipped profile is the `canonical` default of `fmt_source`; no
  profile surface is added.
- `formatting.md` gains the guard sentence and the loud-decline sentence and nothing else.
