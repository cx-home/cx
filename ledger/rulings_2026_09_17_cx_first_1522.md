# cx first — the decisions of the #1522 mini-campaign (owner, 2026-09-17 ~13:50Z: "highest priority"; RULED: CXF-1 … CXF-8)

Owner, on the integrator's admission that it wrote its 2026-09-17 probes over `.cxd` files in Python and kept
the cx surprises it had hit as private notes: *"this needs to be a mini-campaign issue inside the existing
campaign and the highest priority"*. #1522 is that epic. `AGENTS.md` rule 6 already said tooling is written in
CX and another language needs a filed, argued reason; these rows make the reason a tracked issue, extend it to
probes and scratch, and rule the lanes that remove the reasons to reach for anything else. While #1522 runs its
lanes take the code slots ahead of ORD-1's remaining Ring 0 items; the transports and cluster 5 follow.

| Id | Decision |
|---|---|
| **CXF-1** | **The `cx-gap` rule.** When a writer in a cx project — an agent, the integrator, a person — judges another language equal or better for a task, the writer files an issue BEFORE using it: the task in one sentence, the cx attempt or why none was made, and the gap by kind (diagnostic, lint, library, ergonomics, speed, documentation), labeled `cx-gap`. It applies to a probe, a bisect, a one-off edit script and a checked-in tool alike; a plain text edit belongs to the editor, `sed` or `awk` and needs no issue. The other language may then be used for that instance. A `cx-gap` is in the campaign like any bug; the board carries **Open cx-gap** as a row; every closed `cx-gap` adds the playground example that shows the task done in cx (CXF-2's section). `AGENTS.md` rule 6 and the standing rules state it. |
| **CXF-2** | **The everyday examples.** The playground gains one section, `everyday/…`, of about thirty-five examples, each ≤ 20 lines with a graded expected output, batched in three branches: (a) files and directories (read lines, write, append, walk and filter, temp file, paths) · text and regex (`re2` match / capture / replace, split and join, trim and case, `[?str]` templates, padding for a table) · collections as scripts use them (sort by key and descending, dedupe keeping order, top-N, zip, enumerate, a counter, the accumulate pattern); (b) the document probe (parse a `.cx`/`.cxd` as data, count elements, query with a path, diff two files, list the case ids a reader sees) · process, environment, arguments, stdin, exit status · time (format, parse, elapsed under the clock grant) · errors in a CLI (refuse with a message and a non-zero status, retry once); (c) testing your own script with a `.cxd` case · the world (HTTP GET with a header and JSON decode, POST, a local sqlite file, an SMTP send). Every example runs under the grants it names (CXF-6's preset where a probe); the guide renders the section; the playground gates grade it. An example that needs a stdlib verb that does not exist yet names its issue and waits for it — never a shortcut. |
| **CXF-3** | **The diagnostics corpus.** Every refusal code in the registry gets one graded case whose expectation states the form, the position and the fix in the writer's terms; the SILENT classes come first — `[?if]` on an err value taking neither branch, lint arbitration reporting the data-lane failure and hiding the program-lane one, `cx fmt` naming the first comment rather than the one it could not place, the `[title]` swallow (#1521) — because a silent wrong answer is the one outcome the refuse-to-lie posture forbids. An audit branch lists the codes with and without a case (a ledger table, the edit-map shape); fix batches follow BATCH-1's shape. The corpus is mutation-tested: change one diagnostic's text or position and its case fails. A silent wrong answer found anywhere is filed `prio:high` the same hour. |
| **CXF-4** | **Lint parity.** `cx lint` refuses everything the run refuses before evaluation: unbound names, undefined callables, malformed directives (the body-less `[?let]`), purity contradictions, arity, a `[?lib]` that names nothing. Pinned by a sweep step: every corpus program that loads passes lint and every corpus program lint accepts loads — the two sets equal. The known gaps are filed from the trap triage (CXF-8) and fixed in batches. |
| **CXF-5** | **One reader.** #1521's fix shape: every entry point that reads a CX document — the data parser behind `cxlib.parse`, the program reader, the fixture grader — answers the same element tree for the same bytes, or a parity step in `TEST_TARGETS` fails the build naming the file and the first divergence. Fixture first: the `[title …]` shape that swallowed three cases, graded by both readers in one step. |
| **CXF-6** | **The probe preset.** Grants stay deny-by-default — nothing here weakens the capability posture. `cx -e 'PROGRAM'` and the stdin run already exist (cli.md §1); what trips a new writer is spelling the grants for a read-only probe. Ruled: ONE named preset, `--probe`, equal to read on the working tree plus the clock (`--allow-read=<cwd> --allow-clock`), still written on the command line, expanded in `cx --help` and in the primer, refused with the ordinary grant error when a probe writes or reaches the network. A cli.md sentence in §1 (the owner reads it); the branch measures the exact spelling against the grammar and records it. Rejected: a read default with no flag — an implicit grant. |
| **CXF-7** | **The dogfood gate.** `check-cx-first` in `TEST_TARGETS`: a new `.py`, `.sh`, `.mjs` or other-language tool outside the allowed places (the language bindings under `lang/`, the runner bootstrap `scripts/*.sh` set frozen by a manifest, `scripts/playground-gate`'s node harness) fails the build naming the file and CXF-1; the README carries a census — cx tooling versus other, the count and the trend. A file the manifest allows needs no issue; a new one needs a `cx-gap`. |
| **CXF-8** | **The traps become fixtures.** Every CX-trap memory the integrators kept (`reference_cx_*`, `reference_*_traps`, the `?if $err`, `$exists`, `cx:emit`, block-comment, lint-misses-let, yield-nests, probe-accessor notes) is triaged in one pass: a defect becomes an issue with its reproduction (fixture first), a deliberate rule becomes a sentence in the primer's new **surprises** section, and the memory note is retired once its issue or sentence exists. From then on a language surprise is filed with its reproduction before the work continues — the standing rules say so — and the board counts them under Open cx-gap. |
