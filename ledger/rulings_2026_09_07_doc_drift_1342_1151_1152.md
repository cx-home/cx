# Ruling record — three doc-drift trues (2026-09-07)

Decided under the standing rule of 2026-09-07 (no mid-campaign stops; decide on
what is best for CX long-term and record it). Wave 3 of the bug campaign. Each
one is a spec row contradicting either another spec row or the shipped code, so
in every case the ruling is which side is TRUE, established by running the
binary rather than by preferring the prose.

## RULED 1342-A — canonical.md §2.10's TripleQuoted row is the stale one

§2.3 (:168) says canonical "NEVER emits a triple-quoted form — multiline and
control-bearing content escapes per §2.4 inside the ordinary quoted forms".
§2.10 (:385) says TripleQuoted is "Used in canonical when content contains
literal newlines or characters that would require many escapes". Both are
normative and they are direct opposites.

MEASURED, not argued. Content carrying BOTH quote styles and a literal newline —
the exact case §2.10 claims triquote for:

    in   [a "it's got both \" and ' quotes<LF>and a newline"]
    out  [a 'it\'s got both " and \' quotes\nand a newline']

Zero triquotes. §2.3 is the shipped rule, and #1338-A moved the emitter to it
deliberately: `emit_quoted_string`'s local rule used to emit the triquote
spelling when content held both styles, `stdlib/csv.cx`'s canonical text carried
ten `"""`, and lexicon.ebnf [L31a] settles it — "canonical NEVER re-emits the
triquote spelling... raw triple is an INPUT spelling only".

So §2.10's row is trued to §2.3. Triple-quoted remains a valid INPUT spelling;
nothing is removed from the language.

## RULED 1151-A — diagram.md's retired match-cost figure is replaced by the record

`spec/03-approved/std-lib/diagram.md:291` states "~20-45µs/arm measured vs ~2µs
flat" as an approved-spec REVIEW RULE. That measurement was retired three times
over: #1094 made bind-free `[?match]` arms ~0.96x of an if-chain, #1139 made
structural single-arm destructure 0.94-0.98x of a hand-written bind chain, and
#850 preceded both. #1144 W4 already corrected the identical figure in the
corpus/antipatterns/primer, leaving the approved spec as the last carrier.

Replaced with the surviving on-record fact: the hot-path concern is WIDE
ELEMENT-PATTERN dispatch, whose per-arm rollback scales with the program — not
match-vs-if per se. Keeping a retired number in an approved spec as a review
rule means reviewers refuse code on a measurement the project has disproved.

## RULED 1152-A — bus.md is trued to the shipped `::any`, not the reverse

`spec/03-approved/std-lib/bus.md:236` declares `$pattern::pattern`; shipped
`stdlib/bus.cx:26` reads `$pattern::any`. The issue asks which is right.

Ruled: `::any` is right and the spec is trued to it, because **there is no
`pattern` kind**. `is_valid_kind_tag`'s set does not contain it, so `::pattern`
is not a spellable ascription — a spec row using it describes a language that
does not exist. Introducing a `pattern` kind to satisfy a doc row would be
truing the language to a typo, which is the inverse of the rule.

Applies to the `subscribers` / `matches` rows the issue names as carrying the
same spelling.

## RULED 1152-B — stdlib/fp.cx's header note is deleted, not corrected

`stdlib/fp.cx:22` says "this const and stdlib/fp.cx are the same source — edit
both". There is no second const: the module is `$embed_file`'d at
`vcx/code/stdlib_bundle.v:119`. The note instructs the next author to edit a
file that does not exist, which is worse than silence. Deleted rather than
reworded — the embed is visible at the embed site and needs no remote comment.
