# scripts/fmt_corpus_expected_errors.txt — the corpus files `cx fmt` is
# EXPECTED to refuse (RULED: 1348-c).
#
# WHY A NAMED LIST AND NOT A COUNT. `--max-errors N` has no lower bound: when
# someone FIXES one of these the count falls below N and the lane stays green
# with the pin silently loosened, and a genuinely new error is invisible until
# it is the N+1'th. This roster reds BOTH ways — a file that errors and is not
# here, and a file here that has stopped erroring. The second half is the one a
# count cannot express, and it is the half that matters, because one entry
# below is a real defect somebody will fix.
#
# Same shape as the #1350 golden MANIFEST (`99c25169d`): the roster is derived
# from a measurement, checked in, and compared by the gate.
#
# Format: one repo-relative path per line. `#` comments and blank lines ignored.
# Every entry carries its diagnostic, quoted from the census in lane_A_1348m.
