# `scripts/gen_docs` — the LLM onboarding layer generator

Emits `docs/llm/`, the context an LLM assistant needs to write correct CX.
CX post-dates every model's training data, so proficiency has to come entirely
from context the project supplies. This is that context, and it is a
**generated, release-gated artifact** — not a document anyone maintains by
hand. Filed as #938.

## What it produces

| Output | Purpose |
|---|---|
| `docs/llm/primer.md` | The one file to load. ~10–15k tokens: the surface taught through runnable examples, a ring decision table, the core idioms, the anti-patterns. |
| `docs/llm/reference-*.md` | Thin per-area references (data language, code language, stdlib, CLI, platform), loaded on demand. |
| `docs/llm/playbook-xap.md` | The build-a-production-XAP arc: feature grammars and their composition, derived nouns and deriver principals, the authority model, the `*.xap.cxd` deployment document, identity bootstrap, hosting, and the ux-web surface. |
| `docs/llm/contributor.md` + `contributor-{architecture,design,implementation,test}.md` | The contributor's front door (RULED: K11a): the rules for changing CX, each citing its decision, and the reading order; the facts (repository map, pins, module census, step roster, the ledger's `RS-n` statements, the umbrellas) projected by `contributor_facts.cx` from the files that declare them. |
| `docs/llm/llms.txt` | The [llmstxt.org](https://llmstxt.org) index, sectioned by the manifest's `section=` (`start` \| `build` \| `reference`). |
| `docs/llm/llms-full.txt` | Every document above, one concatenation, for a single-URL fetch. |

Three discovery doors serve the same generated text:

1. **`AGENTS.md`** at the repo root — the vendor-neutral agent-instruction
   convention. Hand-authored by nature (agents read it raw from the checkout,
   pre-build), so it stays minimal, carries no examples, and points here.
   A one-line `CLAUDE.md` defers to it.
2. **`/llms.txt` + `/llms-full.txt`** at the published site root. The
   allowlist mirror that used to copy them there retired with the split
   (RULED: RS-11); which of the three answers replaces it is an open letter,
   recorded in `docs-src/llm/manifest.cxd` beside the `[site]` row.
3. **`cx primer`** — the door that cannot go stale. `vcx/cmd/primer.v`
   `$embed_file()`s `docs/llm/primer.md` at compile time, so the text always
   matches the binary and the version header is self-diagnosing.

## How it works

`primer_build.cx` is a single CX program (dog-food: read → `[$cx:parse]` →
replay via `[$process:run]` → write). Templates in `docs-src/llm/` are prose
with `{{…}}` placeholders; `docs-src/llm/manifest.cxd` declares the output set
and the conformance suites the templates may cite.

```
make docs          regenerate docs/llm/
make docs-check    the DRIFT GATE — regenerate in memory, fail on any change
make docs-diff     preview what regenerating would change
make docs-clean    wipe docs/llm/
```

After `make docs`, rebuild (`make build-vcx`) so `cx primer` carries the new
text, then **verify the embed actually landed**:

```
vcx/target/cx primer | diff - docs/llm/primer.md
```

vcx's up-to-date guard decides by mtime over its input dirs (`docs/llm` is one
of them), so a build already in flight when `make docs` rewrote the file can
finish *after* it and leave the guard satisfied by a binary carrying the older
text. `touch docs/llm/primer.md` and rebuild. `make docs-check` cannot see
this — it proves the FILE is fresh, never the EMBED; only
`tools/release-verify.sh`'s `cx primer == docs/llm/primer.md` row does.

## The rule that makes this trustworthy

**Zero hand-maintained example code.** Every code block comes from a
conformance fixture, and every output is re-recorded by *running* the fixture
against the shipped binary. For each cited case the generator requires

> live stdout-else-stderr == the fixture's recorded output

and fails loudly, naming the case, when it does not. A wrong example in an LLM
primer is worse than no example — it poisons in-context learning — so drift is
made structurally impossible rather than reviewed away.

`--check` adds the second half: the regenerated bytes must equal what is
committed. That is what `make docs-check` runs, and it is wired into
`TEST_TARGETS` and `tools/release-verify.sh`, so the cut cannot ship a stale
primer.

## Placeholders

| Placeholder | Expands to |
|---|---|
| `{{VERSION}}` | the repo-root `VERSION` contents |
| `{{EXAMPLE:<id> block}}` | the whole worked example: input document (if any), program, the exact `$ cx …` invocation, and the live output |
| `{{EXAMPLE:<id> code\|data\|out\|raw-out\|cmd}}` | one part of it |
| `{{PAIR:<wrong-id> <right-id>}}` | one anti-pattern entry: heading, the `[why]` prose, both halves as blocks, and the fixture provenance |
| `{{DIRECTIVES}}` | the normative directive registry, projected from the spec's own §4.1 table |
| `{{MODULES:stdlib}}` / `{{MODULES:x}}` | the bundle catalog, projected from each module's `[module-doc]` |
| `{{CXHELP}}` | the binary's own `--help`, captured live |
| `{{REPOS}}` `{{PINS}}` `{{MODULE-CENSUS}}` `{{MODULE-COLUMNS}}` `{{STEPS}}` `{{RULINGS}}` `{{UMBRELLAS}}` | the contributor front door's facts (RULED: K11a), projected by `contributor_facts.cx` from `registry/repos.cxd`, `deps.cxd`, `registry/modules.cxd`, the Makefile's `TEST_TARGETS`, the ledger's `RS-n` statements and the pinned checkouts' umbrella test files; each carries a provenance line and a row floor |

An undeclared suite, an unknown fixture id, an unknown placeholder, an
unclosed `{{`, a duplicate case id across suites, an `[output]` naming an
unknown `section=`, or a fixture whose body nests raw-text delimiters (which
the delimiter slice cannot extract byte-exactly) are all **hard failures**.
Nothing here degrades to a silently empty or mangled block.

## What the gate covers, and the one thing it cannot

`--check` covers three properties:

1. **Example freshness** — every cited fixture is executed and must reproduce
   its recorded output (and exit code, where declared).
2. **Byte drift** — the regenerated bytes must equal the committed ones.
3. **The file set** — a file under `docs/llm/` that no `[output]` entry claims
   is an **ORPHAN** and fails the run. Without that, retiring or renaming an
   output would leave a file that is still committed, still published, still
   linked, and never again regenerated or checked: a stale document with the
   gate green, which is the one failure this layer exists to prevent.
   Retiring a document means deleting the file in the same change that drops
   its entry.

What no gate can see is an **omission** — a rule that was ruled and never
taught. A citation cannot fail for a section nobody wrote. That gap is closed
by review against the rulings ledger, not by machinery, and it is the reason
to re-derive the templates against `ledger/` whenever a surface moves.

**Fixture citations run under least privilege.** The generator invokes each
cited case as `cx [--allow-<cap>…] prog.cx`, with the flags coming from the
case's own `grant=` attribute and nothing else. The conformance harness runs a
no-`grant` case under a full grant, so a fixture that needs a capability but
declares none will pass conformance and fail here — correctly, because the
invocation line the reader copies must be one that actually works. Cite a
capability-free case, or give the case the `grant=` it truthfully needs.

## Adding a section

1. Find a conformance fixture that already proves the point. Prefer that over
   writing one.
2. If none exists, add the case to the right suite. LLM-facing anti-pattern
   pairs belong in `conformance/llm/antipatterns.cxd`, which documents its own
   contract (byte-exact messages, because the wording is what the reader must
   recognise) and supports `[cli-argv]` for invocation-level cases.
3. Declare the suite in `docs-src/llm/manifest.cxd` if it is new.
4. Cite it from a template, run `make docs`, and commit the regenerated
   `docs/llm/` in the same change.

## Relationship to `scripts/gen_guide`

`gen_guide` builds the human-facing guide (`docs/guide/`, HTML, gitignored;
the mirror that used to promote it retired with the split, RULED: RS-11). `gen_docs` builds the
machine-facing layer (`docs/llm/`, Markdown, committed, embedded in the
binary). They share the dog-food principle and nothing else; neither reads the
other's sources.
