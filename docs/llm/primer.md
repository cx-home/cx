## 0. Ten facts that carry most of the distance

CX post-dates your training data. Whatever you remember about a language
called "CX" is not this one. Read these ten before writing anything.

1. **One syntax, two readings.** `[name attr=value child…]` is *the* form. A
   document, a query, a program, and the compiler's own AST are all the same
   shape. There is no separate expression grammar to learn.
2. **`?` marks a directive, `$` marks a value or a call.** `[?for …]` is
   control flow. `[$strings:upper "x"]` is a call. `[row a=1]` with no sigil
   is *data* — an element you just constructed.
3. **Lisp-1, but not a Lisp.** No quoting by default, no macros in the Lisp
   sense, no `car`/`cdr`, no improper lists, no dotted pairs. Brackets are
   not application-by-position: the head names an element or a directive.
4. **Attributes and children are different things.** `[user id=7 [name A]]`
   has one attribute and one child. Attributes are a map on the node;
   children are an ordered sequence. Patterns can match either.
5. **Scalars are typed on read.** `true` is a boolean, `42` an int, `1.5` a
   float, `null` the explicit null, a bare word an atom, quoted text a
   string. Quoting is how you *stop* auto-typing.
6. **Collections are values, not elements.** Sequences are `(a, b, c)` and
   maps are `{key: value}`. A comprehension yields a sequence.
7. **Errors are values, not exceptions.** `[err code=… message=…]` flows
   through the program and propagates out of any element you construct from
   it. There is no `try`/`catch` directive — `[?try]` was retired.
8. **Absence is a value, not a crash.** A missing map key, an out-of-range
   read, an empty match set: each has a defined, distinguishable answer.
9. **Effects are deny-by-default.** Reading a file, dialing a host, or
   reading the clock needs a capability granted on the command line, and a
   denial is an ordinary error value naming the flag that would allow it.
10. **`cx [flags] FILE [program-args…]`.** Flags bind *before* the file.
    Everything after the file belongs to the program. Getting this backwards
    does not produce a usage error — see the anti-patterns in §9.

## 1. Running CX

You can check every claim in this document. Do that rather than trusting it.

```console
cx FILE.cx                       # run a program, or print a document
cx --allow-read FILE.cx          # grant one capability
cx --allow-common FILE.cx        # the common working set (no secret-reveal)
cx -e '[+ 1 2]'                  # a one-liner
cx --data=input.cx prog.cx       # bind a document as $doc / $input
cx --from=json --to=cx in.json   # the convert surface (the data reading)
cx canonical FILE.cx             # strict canonical text — what identity is
cx hash FILE.cx                  # SHA-256 over those canonical bytes
cx lint FILE.cx                  # style + correctness findings
cx primer                        # this document, for the installed binary
```

Exit codes: `0` success, `1` the program produced an error value (or a check
found findings), `2` a usage error. Unknown flags are hard errors — nothing
is silently ignored.

## 2. The shape of CX

### Elements, attributes, children

`input.cx`
```cx
[a href=https://example.com/path Click here]
```

```console
$ cx --from=cx --to=cx input.cx
[a href=https://example.com/path Click here]
```

Attributes only, no children:

`input.cx`
```cx
[input type=text name=q]
```

```console
$ cx --from=cx --to=cx input.cx
[input type=text name=q]
```

Nesting is just children that happen to be elements:

`input.cx`
```cx
[config
  [db host=localhost port=5432]
  [server port=8080]
]
```

```console
$ cx --from=cx --to=cx input.cx
[config
  [db host=localhost port=5432]
  [server port=8080]
]
```

Text and element children interleave freely:

`input.cx`
```cx
[p text [b bold] more]
```

```console
$ cx --from=cx --to=cx input.cx
[p 'text ' [b bold] ' more']
```

### Scalars and their types

`input.cx`
```cx
[active true]
```

```console
$ cx --from=cx --to=cx input.cx
[active true]
```

Quoting is meaningful. A value that must survive as *text* — a version
string, a dotted id, a URL, anything with a space — has to be quoted, and the
canonical form keeps the quotes exactly where they are needed:

`input.cx`
```cx
[m {k: 'a b', j: 'a.b', u: 'https://a.com', ok: 'x', p: 'a/b'} [note a b]]
```

```console
$ cx --from=cx --to=cx input.cx
[m
  {k: 'a b', j: 'a.b', u: 'https://a.com', ok: x, p: a/b}
  [note a b]
]
```

The same rule inside a sequence:

`input.cx`
```cx
[s ('x', 'a b', 'a.b')]
```

```console
$ cx --from=cx --to=cx input.cx
[s (x, 'a b', 'a.b')]
```

### Collections

Sequences `( , )` and maps `{k: v}` are values. Map equality is
order-independent — a map is a map, not a list of pairs:

`input.cx`
```cx
[ignored]
```

`prog.cx`
```cx
[?let [= $z 0] ([= {a: 1, b: 2} {b: 2, a: 1}], [= {a: 1, b: 2} {a: 1, b: 3}], [= {a: 1} {a: 1, b: 2}])]
```

```console
$ cx --data=input.cx prog.cx
(true, false, false)
```

### Comments and raw text

`[; … ]` is a comment element. `[# … #]` is **raw text**: opaque, no entity
expansion, no escaping, no reinterpretation. Raw text is how CX carries a
payload in another language — SQL, a shell script, a regex, prose full of
brackets — without the reader touching a byte.

`input.cx`
```cx
[;a comment]
[p text]
```

```console
$ cx --from=cx --to=cx input.cx
[;a comment]
[p text]
```

### Namespaces

`ns:name` on a head or an attribute is namespaced, and namespaces are part of
identity:

`input.cx`
```cx
[doc xmlns=urn:doc xmlns:xl=http://www.w3.org/1999/xlink
  [xl:a href=https://example.com Link]
]
```

```console
$ cx --from=cx --to=cx input.cx
[doc xmlns=urn:doc xmlns:xl=http://www.w3.org/1999/xlink
  [xl:a href=https://example.com Link]
]
```

## 3. The four rings — take the smallest one that answers your question

CX is built in four rings. The ring answers *how much of CX you have to take
on*. The import contract is enforced by the build, not by convention: Ring 0
imports nothing internal, and no ring may ever reach upward.

| Your task | Ring | What you get | When NOT to use it |
|---|---|---|---|
| Read, write, convert, diff, hash, validate documents | **0 — data** | The reading and the canonical form. No evaluator exists in this ring, so nothing can execute | The moment you need a value computed rather than re-projected |
| Query, transform, generate; run a program | **1 — code** | Directives, CXPath, comprehensions, the stdlib. Effects still need explicit grants | When the result must outlive the process, or a second party must see it |
| Persist, audit, replay; serve HTTP/XSP; host features | **2 — platform** | Store + journal, session layer, HTTP surface, XAP host, drivers | For a value you are about to print — Ring 2 is reached over a network, not embedded |
| Publish/install features; reach CX from another language; agent interop | **3 — ecosystem** | Registry, distribution, bindings, MCP/A2A projections | For anything internal; inside your own program the CX value is better currency |

### Ring 0 — the document *is* the answer

`input.cx`
```cx
[p Hello]
```

```console
$ cx --from=cx --to=cx input.cx
[p Hello]
```

Nothing executed. `cx` read the document and printed the projection asked
for. That is the whole of Ring 0, and it is why Ring 0 is safe to point at
untrusted bytes: there is no evaluator compiled into it to attack.

**When not to use it:** the moment you need a value computed.

### Ring 1 — a program over a document

The canonical Ring-1 shape is a comprehension over a pattern. `[?for]` binds
by *matching shape*, not by index:

`input.cx`
```cx
[users
  [user [name Alice] [email a@x.com]]
  [user [name Bob] [email b@x.com]]]
```

`prog.cx`
```cx
[?for [user [name $n] [email $e]]
       [yield [pair name=$n email=$e]]]
```

```console
$ cx --data=input.cx prog.cx
[pair name=Alice email='a@x.com']
[pair name=Bob email='b@x.com']
```

Read the pattern as a claim about the document: "for every `user` that has a
`name` and an `email`, bind them." Nodes that do not match are skipped, not
errors.

**When not to use it:** when the result has to survive the process, or more
than one party must see it. That is Ring 2.

### Ring 2 — state that outlives the program

The store is content-addressed: `put-doc` returns a handle derived from the
document's canonical bytes, and `get-doc` returns the document. `mem://` is
the capability-free substrate, which is why this runs with no grants at all:

`prog.cx`
```cx
[?lib 'cx-stdlib/store']
[?let [= $s [$store:open "mem://"]] [= $h [$store:put-doc $s [doc [item "hello"]]]] [$store:get-doc $s $h]]
```

```console
$ cx prog.cx
[doc [item 'hello']]
```

Swap `mem://` for a real URL and the same two calls talk to a served store.

**When not to use it:** for a value you are about to print. A store handle is
a promise about durability and identity; if you need neither, stay in Ring 1.

### Ring 3 — the ecosystem edge

Ring 3 is where CX meets everything around it, including agent protocols. The
MCP and A2A shapes are ordinary CX values projected to their wire form —
there is no bespoke serializer anywhere in the path:

`prog.cx`
```cx
[?lib 'cx-x/mcp' :as mcp]
[?lib 'cx-stdlib/json' :as json]
[$json:emit [$mcp:call-tool-request 1 "get_weather" {location: "NYC"}]]
```

```console
$ cx prog.cx
'{"id":1,"jsonrpc":"2.0","method":"tools/call","params":{"arguments":{"location":"NYC"},"name":"get_weather"}}'
```

**When not to use it:** for anything internal. Ring 3 exists for crossing a
boundary.

## 5. The idioms that carry most CX programs

### Bind with a flat multi-binding `[?let]`

`[?let]` takes any number of `[= $name value]` bindings followed by one body.
Bindings are **sequential** — each sees the ones before it — so a nested
`[?let]` per binding is never needed. This fixture is the discriminator that
pins the semantics (`$y` binds the inner `$x`, not the outer shadow):

`prog.cx`
```cx
[?let [= $x 9]
  [?let [= $x 1] [= $y $x]
    [pair x=$x y=$y]]]
```

```console
$ cx prog.cx
[pair x=1 y=1]
```

The house form for three dependent bindings:

`prog.cx`
```cx
[?let [= $a 1] [= $b [+ $a 1]] [= $c [+ $b 1]]
  [row a=$a b=$b c=$c]]
```

```console
$ cx prog.cx
[row a=1 b=2 c=3]
```

### Iterate with `[?for]`

One directive covers map, filter, and reduce. `[in $x SOURCE]` is the
generator (more than one nests), `[where]` filters, `[yield]` emits.

`input.cx`
```cx
[users
  [user [name Alice] [email a@x.com]]
  [user [name Bob] [email b@x.com]]]
```

`prog.cx`
```cx
[?for [user [email $e]] [yield $e]]
```

```console
$ cx --data=input.cx prog.cx
'a@x.com'
'b@x.com'
```

Attribute predicates go in the pattern:

`input.cx`
```cx
[users
  [user active=true [name Alice] [email a@x.com]]
  [user active=false [name Bob] [email b@x.com]]
  [user active=true [name Carol] [email c@x.com]]]
```

`prog.cx`
```cx
[?for [user @active=true [email $e]] [yield $e]]
```

```console
$ cx --data=input.cx prog.cx
'a@x.com'
'c@x.com'
```

`[group-by]` partitions the stream and binds `$count` and the group
aggregates:

`input.cx`
```cx
[users
  [user dept=eng [name Alice]]
  [user dept=sales [name Bob]]
  [user dept=eng [name Carol]]]
```

`prog.cx`
```cx
[?for [user @dept=$d]
      [group-by $d]
      [yield [row dept=$d count=$count]]]
```

```console
$ cx --data=input.cx prog.cx
[row dept=eng count=2]
[row dept=sales count=1]
```

The full grouped shape, with per-group aggregates over a bound key:

`input.cx`
```cx
[ignored]
```

`prog.cx`
```cx
[?let [= $orders [orders
  [order region=east [line qty=2 price=10] [line qty=1 price=5]]
  [order region=west [line qty=3 price=4]]
  [order region=east [line qty=1 price=100]]]]
  [?for [in $o $orders/order] [in $l $o/line]
    [= $r [* $l@qty $l@price]]
    [group-by $o@region]
    [yield [row region=$key revenue=[$sum $group/r] n=$count]]]]
```

```console
$ cx --data=input.cx prog.cx
[row region=east revenue=125 n=3]
[row region=west revenue=12 n=1]
```

`[order-by]` sorts, and takes a direction and multiple keys:

`input.cx`
```cx
[ignored]
```

`prog.cx`
```cx
[?let [= $users [u-set [u name="C" age=30] [u name="A" age=25] [u name="B" age=30]]] [?for [in $u $users//u] [order-by $u/@age desc] [yield $u/@name]]]
```

```console
$ cx --data=input.cx prog.cx
'C'
'B'
'A'
```

`input.cx`
```cx
[ignored]
```

`prog.cx`
```cx
[?let [= $users [u-set [u name="C" age=30] [u name="A" age=25] [u name="B" age=30]]] [?for [in $u $users//u] [order-by $u/@name] [order-by $u/@age desc]
        [yield [r n=$u/@name a=$u/@age]]]]
```

```console
$ cx --data=input.cx prog.cx
[r n=B a=30]
[r n=C a=30]
[r n=A a=25]
```

### Query with CXPath

Paths are values: `$doc/child`, document-rooted `/…`, descendant `//…`, with
predicates. A path works as a `[?for]` source, as an `[?if]` condition
(truthy iff the match set is non-empty), and anywhere a value is expected.

`input.cx`
```cx
[users
  [user [name Alice] [email a@x.com]]
  [user [name Bob]   [email b@x.com]]]
```

`prog.cx`
```cx
//user
```

```console
$ cx --data=input.cx prog.cx
[user [name 'Alice'] [email 'a@x.com']]
[user [name 'Bob'] [email 'b@x.com']]
```

`input.cx`
```cx
[users
  [user active=true  [name Alice]]
  [user active=false [name Bob]]
  [user active=true  [name Carol]]]
```

`prog.cx`
```cx
//user[= $_@active true]
```

```console
$ cx --data=input.cx prog.cx
[user active=true [name 'Alice']]
[user active=true [name 'Carol']]
```

`input.cx`
```cx
[users
  [user active=true  [name Alice]]
  [user active=false [name Bob]]
  [user active=true  [name Carol]]]
```

`prog.cx`
```cx
[$count //user[= $_@active true]]
```

```console
$ cx --data=input.cx prog.cx
2
```

Descendant search with a binding:

`input.cx`
```cx
[section [para [span "hello"] [span "world"]]]
```

`prog.cx`
```cx
[?for [in $s //section] [yield $s//span]]
```

```console
$ cx --data=input.cx prog.cx
[span 'hello']
[span 'world']
```

### Branch with `[?if]`

The clause names are mandatory. `[?if c a b]` is a syntax error, not a
positional shorthand — see §9. `[else]` may be omitted, and a false condition
then yields empty:

`prog.cx`
```cx
[out [ok [?if false [then 'a']]]]
```

```console
$ cx prog.cx
[out [ok ()]]
```

Truthiness is defined per type rather than coerced: zero and empty string are
falsy, an *empty element* is truthy (it exists), and an empty match set is
falsy. That last one is what makes the existence idiom read naturally:

`input.cx`
```cx
[app [flag]]
```

`prog.cx`
```cx
[?if //flag [then "on"] [else "off"]]
```

```console
$ cx --data=input.cx prog.cx
'on'
```

### Destructure with `[?match]`

Arms are tried in order. `[case PATTERN result]` matches shape,
`[when PREDICATE result]` matches a condition, `[case _ result]` is the
wildcard, and `[else]` is the fallback.

`input.cx`
```cx
[doc]
```

`prog.cx`
```cx
[?let [= $n [prose "hello"]] [?match $n
    [case [prose $p] [p $p]]
    [case [code $c] [pre $c]]
    [else ()]]]
```

```console
$ cx --data=input.cx prog.cx
[p 'hello']
```

`input.cx`
```cx
[doc]
```

`prog.cx`
```cx
[?let [= $x 120] [?match $x
    [when [> $x 100] :big]
    [when [> $x 50] :medium]
    [else :small]]]
```

```console
$ cx --data=input.cx prog.cx
:big
```

`input.cx`
```cx
[doc]
```

`prog.cx`
```cx
[?let [= $v "surprise"] [?match $v
    [case 200 :http-ok]
    [case _ :other]]]
```

```console
$ cx --data=input.cx prog.cx
:other
```

Reach for `[?match]` when you are taking a value *apart*. For a plain scalar
branch a flat `[?if]` chain is both clearer and far cheaper — see §9.

### Define with `[?def]`

`[?def name [clauses] (params) body]` defines a function. `scope=public`
exports it. `pure`/`impure` is checked, not decorative. `[returns T]` and
`::T` annotations document by default and are enforced under `--strict`. An
`[effects …]` clause makes the definition a *command* — the unit the
capability and agent-tool layers understand.

`input.cx`
```cx
[doc]
```

`prog.cx`
```cx
[?def greet
  scope=public
  [returns string]
  ($name::string)
  [$concat "hello, " $name]]
[$greet "world"]
```

```console
$ cx --data=input.cx prog.cx
'hello, world'
```

Definitions are module-level, order-independent, and mutually recursive:

`input.cx`
```cx
[doc]
```

`prog.cx`
```cx
[?def even-p ($n)
  [?if [= $n 0] [then true]
                [else [$odd-p [- $n 1]]]]]
[?def odd-p ($n)
  [?if [= $n 0] [then false]
                [else [$even-p [- $n 1]]]]]
[$even-p 10]
```

```console
$ cx --data=input.cx prog.cx
true
```

A def is a first-class value, usable wherever a function is:

`prog.cx`
```cx
[?def dbl ($x) [* $x 2]]
[?map (1, 2, 3) [using $dbl]]
```

```console
$ cx prog.cx
(2, 4, 6)
```

### Import with `[?lib]`

`cx-stdlib/…` is the frozen standard set; `cx-x/…` is the experimental tier

```cx
[$strings:upper "hello"]
```

```console
$ cx prog.cx

```



`[?element]` builds an element whose head is computed; `[?attr]` and

`prog.cx`

### Transform with `[?modify]`

`[?modify]` rewrites a document by matching positions and replacing them. It
is the transform half of the language, and the reason CX needs no separate
template dialect.

`prog.cx`
```cx
[?let [= $d [teams
              [team name="alpha" [member id=1]]
              [team name="beta" [member id=2]]]]
 [?let [= $flag "alpha"]
  [?modify $d //team[= $_@name $flag]/member [set-attr flagged true]]]]
```

```console
$ cx prog.cx
[teams [team name=alpha [member id=1 flagged=true]] [team name=beta [member id=2]]]
```

## 6. Errors and absence

### An error is a value, and position decides

The discriminator is **position, not value**. A source-literal `[err …]` is
data and stays data, so err-shaped documents remain expressible:

`prog.cx`
```cx
[foo [err code='x' message='y']]
```

```console
$ cx prog.cx
[foo [err code=x message=y]]
```

But a *computed* child that evaluates to an err propagates instead of being
adopted, at any depth. Reading a binding is a computed position, so this
propagates rather than building `[report [err …]]`:

`prog.cx`
```cx
[?let [= $e [err code='c' message='m']] [report $e]]
```

```console
$ cx prog.cx
[err code=c message=m]
```

That is the stated cost of the rule, not an accident. The documented escape
is to rebuild from parts — path navigation does not propagate, so `@code` and
`@message` read cleanly off a captured err:

`prog.cx`
```cx
[?let [= $e [err code='c' message='m']] [report [code $e@code] [message $e@message]]]
```

```console
$ cx prog.cx
[report [code 'c'] [message 'm']]
```

A paren **sequence** is not element construction, so it does not propagate —
which is how you collect outcomes including the failures:

`prog.cx`
```cx
[?let [= $e [err code='c' message='m']] ($e, 'kept', [box $e@code])]
```

```console
$ cx prog.cx
([err code=c message=m], kept, [box 'c'])
```

### `[?else]` is the recovery idiom

`[?else VALUE FALLBACK]` yields `VALUE` unless it errored or is absent. There
is no `try`/`catch`; `[?try]` and `[?chain]` were retired from the surface
and now appear only in negative fixtures asserting their rejection.

### Absence has a defined answer

A missing map key reads as empty rather than raising:

`prog.cx`
```cx
[?lib 'cx-stdlib/map']
[$map:get {a: 1} 'zz']
```

```console
$ cx prog.cx
()
```

## 7. Capabilities

The nine capabilities are `read write net env clock random subprocess eval
secret-reveal`. Deny-by-default. A denial is an ordinary error value that
names the flag which would have granted it, so you never guess:

`prog.cx`
```cx
[?lib 'cx-stdlib/io']
[$io:read-file "/var/log/app.log"]
```

```console
$ cx prog.cx
[err code=cx-err:CXER0271 message='E_CAP_DENIED: read capability required for io-read-file; none granted (grant via --allow-read)']
```

`--allow-common` is everything except `secret-reveal`; `--allow-all` includes
it and therefore declassifies secrets. `--allow-net` takes an optional scope
(`--allow-net=example.com:443`). Grant the narrowest thing that works.

`env:argv` and `env:parse-args` are **ungated** — reading your own arguments
is not an effect.

```cx
[?lib 'cx-stdlib/re']
[$re:matches [$re:compile "a+"] "aaa"]
```

### Tables are a data form, not a convention

`[table[…]]` is the columnar block — typed columns, rows as records. It is
first-class, which is what lets `cx table` project it to Parquet/Arrow without
guessing at your intent:

`input.cx`
```cx
[users [table[name::string age::int active::bool]]
  alice 30 true
  bob 25 false
]
```

```console
$ cx --from=cx --to=cx input.cx
[users [table[name::string age::int active::bool]]
  alice 30 true
  bob 25 false
]
```

## 9. Anti-patterns

Each entry below is a fixture *pair*: the form that pattern-matches to a
Lisp, Clojure, or shell prior, and the CX form beside it. Both halves are
executed at generation time, so the wrong half's output is what you will
actually see — not a description of it.

#### cx flags placed after the file

The run surface is `cx [cx-flags] FILE [program-args...]` — the interpreter
convention. Everything AFTER the file is the PROGRAM's argv (#926), so
`--allow-env` there is a string handed to the program, not a grant handed to
`cx`. The capability is never granted and the program dies at its first
effect. Nothing warns you: the flag was consumed, just not by cx.

**Do not write this:**

`prog.cx`
```cx
[?lib 'cx-stdlib/env' as=env]
[probe args=[$count [$env:argv]] home=[$env:var-or-default 'CX_PRIMER_ABSENT' 'unset']]
```

```console
$ cx prog.cx --allow-env
[err code=cx-err:CXER0271 message='E_CAP_DENIED: env capability required for env-var-or-default; none granted (grant via --allow-env)']
```

**Write this:** cx flags placed before the file

`prog.cx`
```cx
[?lib 'cx-stdlib/env' as=env]
[probe args=[$count [$env:argv]] home=[$env:var-or-default 'CX_PRIMER_ABSENT' 'unset']]
```

```console
$ cx --allow-env prog.cx
[probe args=1 home=unset]
```

#### A bare head name silently becomes DATA

CX is homoiconic: `[name …]` is a legal ELEMENT, so a bare head that resolves
to nothing is not an error — it is a document. A misspelled call therefore
succeeds, exit 0, and hands the rest of the program a `[greeet 'world']`
element where a string was expected. The `$` sigil is the assertion "this is
a call": with it, the same typo fails loud and names itself.

**Do not write this:**

`prog.cx`
```cx
[?def greet ($who) [$concat "hello " $who]]
[greeet "world"]
```

```console
$ cx prog.cx
[greeet 'world']
```

**Write this:** The $ call sigil fails loud on the same typo

`prog.cx`
```cx
[?def greet ($who) [$concat "hello " $who]]
[$greeet "world"]
```

```console
$ cx prog.cx
[err code=user-undefined message='no callable "greeet"']
```

<sub>Fixtures: `ap-bare-head-typo-wrong` / `ap-bare-head-typo-right` in `conformance/llm/antipatterns.cxd`</sub>

#### Nested [?let] (the Scheme let* habit)

`[?let]` is ALREADY sequential — each `[= $name value]` sees every binding
before it (EV-LET-SEQ). Nesting adds a scope level per binding and buys
nothing: the two forms below are output-identical. Flat is the house form;
three nested `[?let]`s is a rewrite an assistant should never emit.

**Do not write this:**

`prog.cx`
```cx
[?let [= $a 1]
  [?let [= $b [+ $a 1]]
    [?let [= $c [+ $b 1]]
      [row a=$a b=$b c=$c]]]]
```

```console
$ cx prog.cx
[row a=1 b=2 c=3]
```

**Write this:** Flat multi-binding [?let]

`prog.cx`
```cx
[?let [= $a 1] [= $b [+ $a 1]] [= $c [+ $b 1]]
  [row a=$a b=$b c=$c]]
```

```console
$ cx prog.cx
[row a=1 b=2 c=3]
```

<sub>Fixtures: `ap-nested-let-wrong` / `ap-nested-let-right` in `conformance/llm/antipatterns.cxd`</sub>

#### A wide [?match] on a per-node hot path

`[?match]` is a pattern-matching dispatch, not a switch statement: every arm
carries a pattern that must be compiled and tried. Measured on ARM, one
`[?match]` call costs ~20-45us against ~2us for the equivalent flat
`[?if]`/`[=]` chain — ~500x, which is invisible in a script and ruinous once
it runs once per node of a document. Reach for `[?match]` when you are
destructuring; reach for a flat `[?if]` chain when you are choosing a branch
on a scalar. The pair below proves the rewrite is output-preserving.

**Do not write this:**

`prog.cx`
```cx
[?def kind-of ($n)
  [?match $n
    [case [leaf] 'leaf']
    [case [twig] 'twig']
    [case [branch] 'branch']
    [case [trunk] 'trunk']
    [else 'other']]]
[?for [in $n ([leaf], [twig], [branch], [trunk], [root])] [yield [$kind-of $n]]]
```

```console
$ cx prog.cx
'leaf'
'twig'
'branch'
'trunk'
'other'
```

**Write this:** A flat [?if] chain on the same dispatch

`prog.cx`
```cx
[?def kind-of ($n)
  [?let [= $t [$name $n]]
    [?if [= $t 'leaf']   [then 'leaf']
    [else [?if [= $t 'twig']   [then 'twig']
    [else [?if [= $t 'branch'] [then 'branch']
    [else [?if [= $t 'trunk']  [then 'trunk']
    [else 'other']]]]]]]]]]
[?for [in $n ([leaf], [twig], [branch], [trunk], [root])] [yield [$kind-of $n]]]
```

```console
$ cx prog.cx
'leaf'
'twig'
'branch'
'trunk'
'other'
```

<sub>Fixtures: `ap-wide-match-hot-path-wrong` / `ap-wide-match-hot-path-right` in `conformance/llm/antipatterns.cxd`</sub>

#### `cx eval 'PROGRAM'` — the subcommand takes a FILE

`cx eval` is a legacy ALIAS of the default run action and, like it, takes a
FILE. An inline program needs `-e`. The habit of writing
`cx eval '<source>'` (from other interpreters) makes cx try to OPEN the
program text as a path. Two rules avoid the whole class: run files with
`cx FILE`, and reach for `cx -e 'PROGRAM'` only for a one-liner.

**Do not write this:**

`prog.cx`
```cx
[+ 1 2]
```

```console
$ cx eval '[+ 1 2]'
cx eval: error reading program "[+ 1 2]": failed to open file "[+ 1 2]"; code: 2
```

**Write this:** `cx -e 'PROGRAM'` for a one-liner

`prog.cx`
```cx
[+ 1 2]
```

```console
$ cx -e '[+ 1 2]'
3
```

### One more, from the language itself

`[?if]` requires its clause names. A bare positional branch is refused rather
than guessed at:

`prog.cx`
```cx
[?if true 'a' 'b']
```

```console
$ cx prog.cx
error: cx-err:CXER0001: [?if] expects [then …] / [else …] clause children after the condition — got a bare positional branch expression; write [?if cond [then thenExpr] [else elseExpr]?]
```

## 10. Before you emit CX, check these

1. Every call has a `$`. A bare head is data — that is legal, and silent.
2. Flags come **before** the file; program arguments after it.
3. `[?let]` is flat. One `[?let]`, many `[= …]`, one body.
4. `[?if]` has `[then]` and `[else]` clause names.
5. Every directive you used is in the §4 registry.
6. Every effect has its `--allow-…` grant, and you granted the narrowest one.
7. Strings that must stay text are quoted.
8. You did not write `[?try]`, `[?chain]`, `[?find]`, or `[?par-map]` — all
   retired.
9. You ran it. `cx FILE.cx` is one second; a plausible-looking CX program
   that does not parse costs the reader much more than that.
