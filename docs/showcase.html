    This Site Is Built With CX

    The site you are reading right now is generated by a CX pipeline from CX sources. Every page lives at docs-src/content/<path>.cx as a CX document with a fixed schema; one CXL renderer (scripts/gen_docs/build.cxl) walks the schema and emits the body shape; a shell scaffold pipes the render-tree through cx --md (for the markdown target served on GitHub) and cx --xml (for the HTML target served here). Sidebar nav, code highlighting, the markdown-table to HTML-table transform, the include-style page composition — all of it runs on top of cx eval. No third-party static-site generator; the doc-gen is part of CX dogfooding itself.

    The pipeline shape, in one block.

    shelldocs-src/site.cx                  # nav declaration
docs-src/content/**/*.cx          # one .cx page per route
scripts/gen_docs/build.cxl        # CXL renderer
scripts/gen_docs/scaffold.sh      # orchestration (~300 lines bash)
scripts/gen_docs/style.css        # dark code, sidebar, layout
scripts/gen_docs/playground/      # in-browser sandbox assets
scripts/gen_docs/highlight/       # regex-based syntax highlighter

# pipeline per page:
cx eval build.cxl --data=ctx.cx | cx --md  | post_md  > _docs_staging/<page>.md
cx eval build.cxl --data=ctx.cx | cx --xml | post_html > _site_staging/<page>.html

    The page schema is a CX document the renderer reads, not a template language we ship alongside. Every page declares one element with title layout audience summary, one or more blocks, and a region that survives regeneration. Body items are , , , , , or the marker that becomes this sandbox on the playground page.

    cx[page id=overview
  [meta title=Overview layout=index nav-order=0 audience=evaluator
        summary='One bracket for every data format.']
  [section id=hello title='Hello, CX'
    [prose CX is one syntax for both structured data and prose ...]
    [code lang=cx src=...]]
  [section id=next title='Where to Next'
    [list [item path=quickstart label='Quickstart']]]]

    The renderer (a CXL program) walks //page/section and dispatches per body element name via the XPath self:: axis. Section heading prefers @title over @id; the example-ref resolver looks up //example by id inline; the markdown-table pattern becomes a real HTML <table> in post-process. Nothing in the pipeline is opaque or third-party.

    • CXL reference — every directive the renderer uses
    • CXPath — the queries inside build.cxl
    • Includes — the same pattern build.cxl uses for partials
    • Evaluation model — the directive dispatch underneath

    Read the source: site.cx, build.cxl, scaffold.sh, and any of the docs-src/content/*.cx files in the repo. The doc-gen decisions log at docs-src/internal/DECISIONS.md captures every design choice — schema, sidebar, root-relative versus depth-relative hrefs, parser hazards to work around, link discipline.

    Logfmt Parser in Eight Lines of CXL

    CX as a log-line format. Take a logfmt-style line of key=value records and split it into structured CX.

    shellts=2026-05-20T18:42:00Z level=info request_id=abc123 msg=ok
    cx[?for line :in tokenize(input, '\n') :return
  [event
    [?for kv :in tokenize(line, ' ') :return
      [?let pair :be tokenize(kv, '=') :return
        [pair name=[?= pair[1]] value=[?= pair[2]]]]]]]
    cx[event
  [pair name=ts value=2026-05-20T18:42:00Z]
  [pair name=level value=info]
  [pair name=request_id value=abc123]
  [pair name=msg value=ok]]

    Build System in CX

    Targets, depends, run — declared in CX, evaluated by a thirty-line CXL driver.

    cx[targets
  [target name=all       depends='lib bin']
  [target name=lib       depends='src/foo.o src/bar.o'  run='ar rcs lib.a src/foo.o src/bar.o']
  [target name=bin       depends='main.o lib'           run='cc -o bin main.o lib.a']]
    cx[?def build :params [name] :body
  [?for t :in //target[@name = $name] :return
    [?for d :in tokenize(t/@depends, ' ') :return [?build d]]
    [?run t/@run]]]
[?build 'all']

    Config Template With Inline Substitutions

    Config and interpolation in one file — same dialect everywhere.

    cx[server
  host=[?= //env/@host]
  port=[?= //env/@port]
  workers=[?if [//env/@env = 'prod', 32, 4]]
  cache=[?if [//env/@env = 'prod', /var/cache/app, /tmp/cache]]]
    shellcx eval server.cxl --data=env.prod.cx --to=toml

    Typed CSV via the Table API

    Columns declare types. The CSV round-trip survives them.

    cx[:table
  [:col name='date'   type='date']
  [:col name='symbol' type='string']
  [:col name='price'  type='decimal']
  [:col name='volume' type='int']
  [:row [date 2026-05-20] [symbol AAPL] [price 184.32] [volume 12000000]]
  [:row [date 2026-05-20] [symbol MSFT] [price 421.18] [volume  8400000]]]
    shellcx table dump prices.cx --to=csv > prices.csv
cx table load prices.csv --to=cx     # types reattached from header

    Inline Arrow IPC

    libcx_arrow turns a CX table into an Arrow record batch with no copies in the type plumbing — decimal stays decimal, dates stay dates, no ad-hoc string round-trips.

    pythonimport cx, pyarrow as pa
batch = cx.table_to_arrow(cx.parse(open('prices.cx').read()))
print(batch.schema)
