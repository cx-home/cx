    FAQ

    Working answers to the questions adopters ask in the first thirty minutes.

    Read This First

    Working answers for the questions adopters ask in the first thirty minutes. For the format itself see the Tutorial; for the formal grammar see the Grammar (EBNF) reference; for the comparison with other formats see the vs JSON / YAML / TOML / XML page.

    Why CX Instead of JSON?

    JSON has no comments and no type fidelity beyond IEEE 754 doubles. That is fine for API payloads but punishing for configuration (rationale belongs next to the values it explains) and for data exchange that involves big integers, decimals, dates, or anything outside the JSON value tower. CX keeps the round-trip: cx --json file.cx then cx --from json brings bigints, decimals, dates, and types back unchanged. JSON itself silently breaks any integer over two-to-the-53rd.

    Use JSON when the consumer is fixed and the data fits the JSON value tower. Use CX when the same data needs to round-trip into and out of multiple consumers without losing meaning.

    Why CX Instead of YAML?

    YAMLs implicit typing is the load-bearing problem: country: NO parses as false; version: 1.10 parses as 1.1; port: 022 parses as octal 18. CX inverts the rule: leading-zero tokens are strings (so 02134 stays the string 02134), colon-type annotations make the type explicit, and there is no implicit boolean coercion of strings.

    YAMLs significant whitespace is hostile to programmatic generation — a stray tab corrupts a deeply nested document. CX uses brackets, which programmatic emitters cannot accidentally break.

    Why CX Instead of TOML?

    TOML is excellent for flat, table-shaped configuration. It struggles with deep hierarchy: bracket-dot headers get repetitive, and mixing arrays-of-tables with inline tables leaks complexity. CX nests freely at any depth with no syntactic penalty, and exports to TOML losslessly when the source happens to fit TOMLs shape.

    Why CX Instead of XML?

    XML has the strongest schema and namespace story of any text format in wide use. It is also verbose: closing tags repeat, attribute quoting is mandatory, and the XML declaration and DOCTYPE machinery is cumbersome. CX gives you XMLs structural power attributes mixed content namespaces id/idref without the verbosity. A CX document that round-trips to XML is typically half the byte count.

    Why CX Instead of Markdown?

    Markdown is the right format for prose with light structure — articles, READMEs, blog posts. It has no opinion about types, schemas, or data. CX subsumes Markdown for the cases where prose and structured data live together. If you only need prose, stay in Markdown.

    When Is CX the Wrong Choice?

    • Hot-path JSON for high-throughput APIs. Use JSON; the parsing ecosystem is faster and more universal.
    • Kubernetes and the Helm ecosystem. Stay in YAML; the tooling expects it.
    • Pure prose documents. Stay in Markdown.
    • Database export with type-fidelity guarantees. Use Parquet or Arrow.

    Is CX Production-Ready?

    v0.7.0 is the API and format-stability boundary through 1.0. C ABI symbols are append-only from here forward; ast-bin format versions are forward-compatible; the cross-binding conformance suite gates every release. Adopt today and expect format stability through 1.0 with incremental tooling improvements.

    Can I Adopt Incrementally?

    Yes. Every CX file converts losslessly to one or more of the five formats it interoperates with. Use CX as your source of truth and emit YAML for Kubernetes, TOML for static-site configs, and Markdown for docs; or author in JSON / YAML / TOML and convert to CX when you need comments, types, or hierarchy.

    Which Language Can I Use CX From?

    Ten implementations, all backed by the same V core. Each binding wraps the libcx C ABI; the API shape differs idiomatically but the underlying capability set is the same.

    • V — the native reference implementation
    • Python — ctypes wrapper
    • Go — cgo wrapper
    • Rust — extern C wrapper
    • TypeScript — koffi wrapper for Node
    • Java — JNA wrapper
    • Kotlin — JNA wrapper
    • Swift — clang interop
    • C-sharp — P/Invoke wrapper
    • Ruby — FFI wrapper

    How Do I Migrate From JSON / YAML / TOML / XML / Markdown?

    shellcx --from json existing.json > existing.cx
cx --from yaml existing.yaml > existing.cx
cx --from toml existing.toml > existing.cx
cx --from xml existing.xml > existing.cx
cx --from md existing.md > existing.cx

    The reverse direction is the default — cx --json file.cx writes JSON to stdout.

    Why Brackets Instead of Braces, Indentation, or Tags?

    Brackets are the lightest balanced delimiter not in heavy use already. Braces are JSON; mixing braces with the rest of CX would create constant visual collision. Indentation breaks under programmatic generation. Tags double the character count for every construct and force closing-tag repetition. Brackets also pun usefully: is the thing called name, which matches how humans write structured outlines on whiteboards.

    What Types Does CX Support?

    Atomic types: int arbitrary range sized variants i8 i16 i32 i64 u8 u16 u32 u64, float IEEE 754 sized variants f32 f64, bool, string, null, date, datetime, bytes, decimal (arbitrary precision), bigint (arbitrary precision), and arrays of any of these. Compound types are inherent in the structure: any element with attributes is a record; any element with same-named children is a collection; the :table block is a typed table.

    Why Colon-Type Annotations?

    CX auto-types most values that look unambiguously like one type — 8080 becomes int, 3.14 becomes float, true becomes bool, 2026-01-01 becomes date. The colon-type annotation is for cases where the auto-typer would guess wrong, where you want a stricter range (:u16 rejects values over 65535), or where the value should keep a specific runtime type.

    cx[port :u16 8080]

    Why Plus-Flag and Minus-Flag Boolean Sigils?

    Boolean attributes are the most common attribute kind in configuration. Writing tls=true tls_v1_3=true http3=true debug=false is heavier than +tls +tls_v1_3 +http3 -debug. The sigils are pure syntactic sugar.

    Why Does [zip 02134] Produce a String?

    Leading-zero tokens stay strings unless the prefix is 0x (hex), 0o (octal), or 0b (binary). The rule is deliberately predictable: leading-zero numerics are typically identifiers postal codes area codes BIC codes account numbers where the leading zero is data, not a numeric value.

    What Is :decimal For?

    Arbitrary-precision decimal — for money, scientific quantities, or any value where IEEE 754 binary floats would lose precision. 0.1 plus 0.2 is 0.30000000000000004 in float; in :decimal it is 0.3. Consumer bindings map :decimal to their languages decimal type — Python Decimal, Java BigDecimal, .NET decimal, Ruby BigDecimal.

    What Is :table?

    A row-major-in-text, column-major-in-binary tabular block. In the binary cx_to_data_bin form, :table rows are stored column-major and run 5 to 10 times smaller than equivalent element-per-row encoding for large datasets.

    cx[stocks :table[ticker:string price:f64 volume:u32]
  AAPL 192.45 38291092
  GOOG 142.30 18234567
  MSFT 415.18 23456789
]

    What Is Logfmt Mode?

    A CX file made entirely of bare top-level key=value attributes. Each line parses as a synthetic Element. Log streams are valid CX. You can cx --json logs.cx and get a JSON array of typed log records — no separate logfmt parser needed.

    cxts=2026-05-07T10:30:00Z level=info svc=api req_id=abc123 latency_ms=45
ts=2026-05-07T10:30:01Z level=warn svc=api req_id=def456 latency_ms=210 slow=true

    Is There an LSP?

    Yes. cx lsp speaks LSP over stdio — any editor with an LSP client can drive completion, hover, go-to-definition, diagnostics, formatting, and rename refactors against CX, CXL, and CXS sources. Editor installer scripts under tooling/install set up VS Code and Neovim out of the box.

    Is There Syntax Highlighting for My Editor?

    The tree-sitter grammar at tooling/tree-sitter-cx covers all of v0.7.0. VS Code and Neovim integrations live at tooling/vscode and tooling/neovim.

    Will CX Scale to Gigabyte Files?

    Streaming parse and emit are both supported — process arbitrarily large inputs without reading them fully into memory, callback-driven. For terabyte-scale data, use a binary columnar format Parquet Arrow; CX has bridges to both via libcx_arrow.

    Is CX Thread-Safe?

    The C ABI is documented per-symbol with thread-safety classes. All format converters are stateless and can run concurrently across threads on disjoint inputs. The Boehm GC underneath libcx requires cx_thread_register on each calling thread; Tier-1 bindings handle this automatically at every FFI chokepoint.

    How Do I Contribute?

    The project lives at github.com/cx-home/cx. Bug reports, doc fixes, and pull requests are welcome. For format-design questions or proposed grammar changes, file an issue first; a recorded design decision is a prerequisite for any breaking change.

    How Do I Report a Security Issue?

    Through GitHubs private vulnerability reporting at github.com/cx-home/cx/security/advisories/new. Do not file a public issue for security-sensitive bugs.

    Why Does My Embedded Code Get Garbled?

    The bracket-pipe block-content form is parsed as CX, so child-element brackets inside it open new elements. If your code contains brackets, braces, or quotes, the parser will mangle it. Use the bracket-hash raw-text form instead — nothing inside is parsed, and the terminator is hash-bracket.

    cx[code [#
  for (let i = 0; i < arr.length; i++) {
    console.log(arr[i]);
  }
#]]
