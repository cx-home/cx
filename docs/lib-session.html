    session

    The server-held (principal, tenant) session for a web app. A small, durable association between a verified external identity and a tenant-scoped principal — established by attach, looked up by of, and torn down by detach. One session can carry multiple concurrent clients (a human's browser and their agent mirror-attach to it) and survives the death of any individual client. The attach transports converge on one session model: Bearer tokens for agents and service clients, an opaque-session-id cookie (with synchronizer-token CSRF defense) for browsers, DID/XSP proofs for peers — and attach-guest for the proofless anonymous floor, minting the same cookie-carried session for pre-login state. It delegates all token verification to crypto and all transport to http, adding no cryptography or sockets of its own.
