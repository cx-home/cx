    Cookbook

    Task-shaped recipes. I want to X — here is the X.

    Read This First

    Each recipe is a concrete task with the smallest CX or CXL that solves it. Browse the headings, find the one that sounds like what you are trying to do, copy-paste, and adapt. Each recipe links to the deeper reference where the underlying mechanism is documented.

    Convert YAML to JSON

    shellcx convert config.yaml --to=json > config.json

    Auto-detected by extension. Override with --from when the extension lies.

    Convert TOML to YAML

    shellcx convert config.toml --to=yaml > config.yaml

    Extract a Single Value

    shellcx eval -e '[?= //server/@host]' --data=config.cx

    The -e flag takes the template inline; --data is the input file. The CXPath finds the host attribute of any server element at any depth.

    Filter Records by Attribute

    Run cx eval -e with a CXL inline that filters by predicate. The CXPath predicate //user[@role='admin'] selects only admins.

    shellcx eval template.cxl --data=users.cx

    Count Records

    shellcx eval -e '[?= count(//order)]' --data=orders.cx

    Validate Against a Schema

    shellcx validate order.cx --schema=order.cxs
cx validate order.cx --schema=order.cxs --mode=strict
cx validate order.cx --schema=order.cxs --fail-on=warn

    Exit 0 if no diagnostics at or above fail-on, 1 if any, 2 on I/O or schema-load failure.

    Compute the Canonical Hash

    shellcx canonical menu.cx
cx hash menu.cx
cx eq a.cx b.cx

    Use the hash for content-addressing, cache keys, or signing. cx eq returns exit 0 iff canonical(a) equals canonical(b).

    Semantic Diff Between Two Documents

    shellcx diff old.cx new.cx                          # unified
cx diff --format=json   old.cx new.cx
cx diff --format=summary old.cx new.cx

    The diff walks the canonical form so comment and whitespace changes do not show up.

    Lint a File

    shellcx lint config.cx
cx lint config.cx --only=CX-L005
cx lint config.cx --disable=CX-L001,CX-L007

    Format / Re-Indent

    shellcx fmt config.cx                # in-place if you redirect
cx fmt --check config.cx        # exit non-zero if not canonical
cx fmt < input.cx > output.cx

    Generate a Config From a Template

    cx[server
  host=[?= //env/@host]
  port=[?= //env/@port]
  workers=[?if [//env/@env = "prod", 32, 4]]
  cache=[?if [//env/@env = "prod", /var/cache/app, /tmp/cache]]]
    shellcx eval server.cxl --data=env.prod.cx --to=toml > server.toml

    Stream a Large File

    pythonimport cx
with open("events.cx", "rb") as f:
    for event in cx.stream(f):
        if event.kind == "element_start" and event.name == "error":
            print(event.attrs)

    RSS stays bounded regardless of input size. Tier-1 bindings V Python Go ship the streaming reader and writer; Tier-2/3 follow in v0.7.x.

    Write a Stream

    pythonwith cx.stream_writer(open("out.cx", "wb")) as w:
    for record in fetch_records():
        w.write(record)

    Compose a Document From Files

    cx[server
  [?cx include=lib/defaults.cx]
  port=8080
  log-level=info]
    shellcx --cx --include-root=./conf server.cx > resolved.cx

    The parse-time include splices the contents of lib/defaults.cx in place. The eval-time variant is for dynamic includes inside CXL templates.

    Render a Template With Includes

    cx[?include 'partials/header.cxl']
[?for item :in //order/line :return [?include 'partials/line.cxl']]
[?include 'partials/footer.cxl']
    shellcx eval order.cxl --data=order.cx --include-root=./templates

    Emit a Table as CSV

    shellcx table dump orders.cx --to=csv > orders.csv
cx table dump orders.cx --to=tsv > orders.tsv
cx table dump orders.cx --to=psv > orders.psv

    The CSV header carries the column types so the reverse direction (cx table load) reconstructs them.

    Read a Parquet File Into CX

    shellcx table load orders.parquet --to=cx > orders.cx

    Phase A (Arrow round-trip) ships at v0.7.0; Phase B (Parquet writer) and Phase C (read-side schema inference) follow in v0.7.x.

    Use an ID-Based Reference

    cx[order #o1234 customer=alice
  [line item=@margherita count=2]
  [line item=@salad count=1]]
[receipt order=@o1234]

    Hash declares an id; at-sigil references it. Identifiers are unique within the documents scope.

    Share Defaults Across Records

    cx[defaults &shared timeout=30 retries=3]
[server *shared name=api]
[server *shared name=worker retries=5]

    Ampersand declares an anchor; asterisk merges from it. Local fields override; missing ones inherit.

    Iterate Multiple Documents in One File

    shellcx parse multi.cx --to=json     # writes a JSON array

    Top-level three-dashes on a line by themselves separate independent documents. cx parse walks each in order; cx --json emits an array.

    HTML-Safe Templating

    cx[?cx output-target=html]
[h1 [?= //page/@title]]
[?for u :in //user :return [li [?= u/@name]]]

    switches the evaluator into context-aware escaping. Substituted values that contain less-than / greater-than / ampersand / quotes escape correctly with no manual sprintf.

    Emit Structured Log Records

    cx[?cx use-module=log log-level=info]
[?log:info ['sale', {pizza: 'Margherita', price: 12}]]
[?log:warn ['low-stock', {pizza: 'Diavola', stock: 2}]]

    The log module emits structured records to stderr (default) or a configured sink. Fields are a map; level is one of trace / debug / info / warn / error.
