Tutorial

Walk CX from atoms to closures in one scrollable page with exercises.

Read This First

This tutorial walks CX from the smallest piece to the fullest expression in one scrollable page. Each chapter introduces one shape, shows it in context, and ends with two or three exercises you can run with cx --ast or cx --json. Pace yourself.

Assumed background: familiarity with at least one of JSON, YAML, TOML, or XML. CX assumes you know what an object, array, scalar, and attribute are.

Chapter 1. Why CX Looks the Way It Does

Most projects need two kinds of file: typed configuration in nested structures, and documents with prose plus structure. JSON, YAML, and TOML are optimized for the first; Markdown, HTML, and XML for the second. Projects end up with multiple file formats and multiple parsers.

CX is one syntax for both. The same parser handles a Kubernetes-style config and an article with mixed-content prose. Five design constraints picked the shape: one construct, no indentation semantics, optional quoting, types first-class, lossless conversion to existing formats.

Chapter 2. Elements

Every CX node is a bracket pair with a name and an optional body. Editors balance brackets natively; code folding works without parser hooks. The opening name appears once; nothing repeats at close.

cx[p Hello, World]

Exercises. Save the snippet as hello.cx and run cx --ast hello.cx. Add a child element and re-run. Then run cx --json on the same file.

Chapter 3. Attributes

Attributes are name=value pairs after the element name. Bare values auto-type: 8080 becomes int, 3.14 becomes float, true becomes bool, 2026-01-01 becomes date. Leading-zero tokens stay strings — 02134 stays the string 02134 — to avoid the YAML Norway problem.

cx[server host=api.example.com port=8080 ssl=true]

Exercises. Add three more attributes and check what type cx assigns each. Quote a value containing a space and inspect the AST.

Chapter 4. Types

CX auto-types most values; for the rest, a colon-type annotation pins the value or body type. Sized variants carry range constraints that validate at parse time.

cx[port :u16 8080]

Sized integer variants i8, i16, i32, i64, u8, u16, u32, u64; sized float f32, f64; arbitrary-precision decimal and bigint. Exercises. Try setting :u16 to 70000 and observe the error. Compare 12 vs 12 in cx --ast.

Chapter 5. Element Bodies

A body holds Text, Scalar, child Element, or collection literal in source order. Mixed content is first-class — text and structure interleave the way they do in XML.

cx[para Try the [b Margherita] — our [em best seller], hand-tossed daily.]

Triple-quoted bodies preserve multi-line content verbatim. See 50 Ways to Love Your CX Data example 21 for the triple-quoted body shape. Exercises. Write an article with h1, p, em, and a children; convert with cx --md. Inspect a triple-quoted body with cx --ast.

Chapter 6. Comments

Hash line comments live outside element bodies. Bracket-dash block comments live inside elements and can span lines.

cx[shop port=8080 [menu [pizza name=Margherita]]]

Add a hash line above the shop element; add a bracket-dash inline. Exercises. Check what cx fmt preserves and what cx canonical drops.

Chapter 7. Sigils

Five sigils give CX structural reach beyond name and attribute. The at-sigil prefixes attributes in CXPath and references in body position. The ampersand declares an anchor; the asterisk merges from an anchor; the hash declares an id; the colon pins a data type.

cx[defaults &shared timeout=30 retries=3]
cx[server *shared name=api]

Exercises. Declare an anchor and merge from it in two servers. Add ids to three pizza elements; reference them from a separate order element.

Chapter 8. Collection Literals

Three first-class collection shapes. Sequence with parens flattens; array with square brackets preserves nesting; map with braces gives named key-to-value entries.

cx[pizza toppings=(cheese, basil, oil)]
cx[pizza prices={small: 9, medium: 12, large: 15}]

Exercises. Build a config with all three shapes; convert with cx --json. Note the difference between a b c and — sequence flattens, array preserves nesting.

Chapter 9. Typed Tables

A colon-table block declares column names and types. Each non-blank line below is a row; cells parse against the declared column types. Round-trips to CSV with types preserved via the header row. In the binary ast-bin form, rows are stored column-major and run 5 to 10 times smaller than equivalent element-per-row encoding.

cx[orders :table[item:string qty:u32 paid:bool when:date]
  Margherita 2 true  2026-05-09
  Hawaiian   1 false 2026-05-09]

Exercises. Convert with cx table dump --to=csv; check the header. Add a row whose qty exceeds u32 max and observe the error.

Chapter 10. Multi-Document Files

A single CX file can hold multiple top-level documents separated by three dashes on a line by themselves. Same separator as YAML; each side parses as an independent document. cx parse iterates them; cx --json emits an array.

Exercises. Write two top-level documents with the separator between them and iterate with cx parse.

Chapter 11. Six Surface Dialects

The same tree parses and emits as CX, XML, JSON, YAML, TOML, or Markdown. Each dialect captures the subset of the data model it can represent.

shellcx parse pizza.cx --to=yaml

Exercises. Take a YAML config; run cx --from yaml file.yaml; check which features convert cleanly and which are dropped. The Comparison page documents the loss matrix per dialect pair.

Chapter 12. CXL: Directives Inside Data

CXL is CX that does things. A directive is an element whose name starts with a question mark. Directives parse as regular CX and evaluate against the surrounding tree when cx eval runs the document.

cx[h1 [?= //page/@title]]

Exercises. Save the h1 example and run cx eval with --data pointing at a CX file that has a page element. Use a ?for and a ?if together to format an order with a stock badge per item.

Chapter 13. CXPath

CXPath is the query language inside CXL. Paths separated by slashes; predicates in square brackets; axes for navigation by relationship.

cx//pizza[@price > 10]

Exercises. Write a CXPath that finds all toppings of a pizza named Margherita. Use count() to count pizzas above 10 euros.

Chapter 14. Let and For

?let binds a name once and reuses it. ?for iterates a CXPath result.

cx[?let tax :be 0.22 :return [?= @price * (1 + tax)]]

Exercises. Compute the grand total of all pizzas after a 10 percent discount; use ?let for the discount factor.

Chapter 15. Filters

Filter directives transform values. Compose with pipes or nest them.

cx[?= @name |> trim |> upper]

Exercises. Take a name attribute with leading and trailing whitespace; produce a canonical lower-case form.

Chapter 16. Multi-Branch Conditional

The multi-branch ?if shape avoids the else-if ladder. Each branch is a condition-value pair; the wildcard branch is the catch-all.

Exercises. Classify a temperature reading as cold or mild or hot with a multi-branch ?if.

Chapter 17. Named Templates

?def defines a reusable fragment. ?use invokes it; parameterised templates take positional args.

cx[?def line :params [item] :body [tr [td [?= item/@name]] [td [?= item/@qty]]]]

Exercises. Define a template for an HTML link card; use ?for to render a list of pizzas as cards.

Chapter 18. Includes

Two include forms share one resolver. The parse-time form expands files before the document reaches downstream tools; the eval-time form expands files while a CXL template runs.

shellcx --xml --include-root=./conf config.cx

Exercises. Create lib/defaults.cx with a few attribute lines; include it in two different parent elements.

Chapter 19. Identity

Every CX document has a canonical form: presentation stripped, attribute order normalised, anchors renumbered. cx hash returns the SHA-256 of those canonical bytes. Two documents with the same data have the same hash, in any dialect.

shellcx hash menu.cx

Exercises. Take a CX file; reorder its attributes; add a comment. Verify cx hash returns the same hash and cx eq reports them equal.

Chapter 20. Putting It All Together

Every shape composes naturally with every other. The whole-shop example at 50 Ways to Love Your CX Data example 50, and the whole-kitchen CXL example at 50 Ways to Love Your CXL Code example 50, exercise every shape in this tutorial inside a single working document.
