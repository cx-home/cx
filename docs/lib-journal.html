    journal

    An append-only, hash-chained, tenant-partitioned event log and the deterministic projection of that log into state. Open or attach a journal over a store backend, append attributed events (each returning a committed [entry] with its sequence, content hash, and predecessor link), read / slice / query ranges, and fold the log into a state projection. The chain is deterministic — replayable, dry-runnable, and hash-verifiable — which is the entire reason it exists. snapshot, retain, and compact accelerate and bound replay as derived artifacts; they never edit the live chain, so append-only and chain integrity hold permanently.

    journal:open

    [$journal:open] -> element — Open a journal over a store backend URL for one tenant, creating or attaching to its hash chain.

          [?lib 'cx-stdlib/journal']
[?let [= $j [$journal:open "mem://acme" "acme"]]
  [$journal:append $j [do :refund] {actor: "ops" authority: "d-77"}]]
    
          [entry seq=1 tenant=acme actor=ops authority=d-77 ts='1970-01-01T00:00:01Z' prev-hash='genesis:' payload='sha2-256:1c28ab1fd422c356d61afc4be98fe2ff836d21b306487a4d67a62b40fc762ec5' hash='sha2-256:902dfe8cf83616e030e70ec30429c632601d4bd29308b757049706a3afb218a4' [event [do :refund]]]

    journal:attach

    [$journal:attach] -> element — Attach a journal to an already-open store handle for one tenant, reusing its connection.

          [?lib 'cx-stdlib/store']
[?lib 'cx-stdlib/journal']
[?let [= $s [$store:open "mem://r"]]
[= $j1 [$journal:attach $s "acme"]]
[= $a [$journal:append $j1 [a 1] {actor: "u" authority: "g"}]]
[= $b [$journal:append $j1 [b 2] {actor: "u" authority: "g"}]]
[= $c [$journal:close $j1]]
[= $j2 [$journal:attach $s "acme"]]
  [$journal:verify $j2]]
    
          [verification valid=true checked-from=1 checked-to=2 head-hash='sha2-256:1d4f5830f65cd9c6b37aa82309376cb3933b6ff91b7d0c7ef877d4403c9dabb0']

    journal:close

    [$journal:close] -> null — Close the journal handle; subsequent operations on it raise CXER4612.

          [?lib 'cx-stdlib/journal']
[?let [= $j [$journal:open "mem://t" "acme"]]
[= $x [$journal:close $j]]
  [$journal:append $j [a] {actor: "u" authority: "g"}]]
    
          cx-err:CXER4612

    journal:source

    [$journal:source] -> [sequence element] — Return one stream's retained committed entries in seq order — the journal-stream source-reference form for planar comprehensions (code.md 7.8).

          [?lib 'cx-stdlib/journal']

[= $e1 [$journal:append $j [a 1] {actor: "u" authority: "g" stream: "orders"}]]
[= $e2 [$journal:append $j [a 2] {actor: "u" authority: "g" stream: "orders"}]]
[= $e3 [$journal:append $j [b 9] {actor: "u" authority: "g"}]]
  [$count [$journal:source $j "orders"]]]
    
          2

    journal:head

    [$journal:head] -> element — Return the head [entry] from the handle's CACHED view, or absence if the log is empty. Makes NO freshness claim (stream 7 F1): under a second writer — another process on a local root, another client behind a read-only view — it may report a stale position with no signal; it satisfies neither :read-your-writes freshness nor a declared-fresh need. A caller that needs the durable head uses the distinct impure verb head-fresh.

          [?lib 'cx-stdlib/journal']
[?let [= $j [$journal:open "mem://t" "acme"]]
  [$journal:head $j]]
    
          ()

    journal:head-fresh

    [$journal:head-fresh] -> element — Return the head [entry] after re-resolving the durable head through the SUBSTRATE (stream 7 F1 — the declared-fresh head verb): a read-only local handle re-takes its private snapshot view from disk through the normal capability-gated open path; a remote-backed handle asks the daemon; mem:// answers the live instance. Impure by contract; absence on an empty stream, like head.

          [?lib 'cx-stdlib/journal']
[?let [= $j [$journal:open "mem://cst-098" "acme"]]
[= $a [$journal:append $j [x 1] {actor: "u" authority: "g"}]]
[= $b [$journal:append $j [x 2] {actor: "u" authority: "g"}]]
[= $h [$journal:head $j]]
[= $hf [$journal:head-fresh $j]]
  [heads cached=$h/@seq fresh=$hf/@seq]]
    
          [heads cached=2 fresh=2]

    journal:streams

    [$journal:streams] -> [sequence element] — List the distinct stream names present in the journal. A tenant-wide composition over these streams is NOT a cut (stream 7 F8): each stream's head is snapshotted independently, with no cross-stream linearization claimed — a verifiable multi-stream cut is :at-head-set, the signed snapshot head-set.

          [?lib 'cx-stdlib/journal']
[?let [= $j [$journal:open "mem://t" "acme"]]
[= $a [$journal:append $j [x 1] {actor: "u" authority: "g" stream: "s1"}]]
[= $b [$journal:append $j [x 2] {actor: "u" authority: "g" stream: "s1"}]]
[= $c [$journal:append $j [y 1] {actor: "u" authority: "g" stream: "s2"}]]
  [$journal:streams $j]]
    
          (s1, s2)

    journal:fold

    [$journal:fold] -> any — Fold ONE stream into a state projection with a pure reducer and initial value. A tenant-wide state composed from per-stream folds is NOT a cut (stream 7 F8): each stream's head snapshots independently, no cross-stream linearization is claimed — the verifiable cut is :at-head-set (the signed snapshot head-set).

          [?lib 'cx-stdlib/journal']
[?let [= $j [$journal:open "mem://t" "acme"]]
[= $e1 [$journal:append $j [a] {actor: "u" authority: "g"}]]
[= $e2 [$journal:append $j [b] {actor: "u" authority: "g"}]]
[= $e3 [$journal:append $j [c] {actor: "u" authority: "g"}]]
  [$journal:fold $j [?fn ($a $e) [+ $a 1]] 0]]
    
          3

    journal:fold-slice

    [$journal:fold-slice] -> any — Fold a from..to range of the log into a state projection.

          [?lib 'cx-stdlib/journal']
[?let [= $j [$journal:open "mem://t" "acme"]]
[= $e1 [$journal:append $j [a] {actor: "u" authority: "g"}]]
[= $e2 [$journal:append $j [b] {actor: "u" authority: "g"}]]
[= $e3 [$journal:append $j [c] {actor: "u" authority: "g"}]]
  [$journal:fold-slice $j [?fn ($a $e) [+ $a 1]] 0 2 3]]
    
          2

    journal:fold-value

    [$journal:fold-value] -> any — Fold an already-read entry sequence into state, without touching the journal.

          [?lib 'cx-stdlib/journal']
[?let [= $j [$journal:open "mem://t" "acme"]]
[= $e1 [$journal:append $j [a] {actor: "u" authority: "g"}]]
[= $e2 [$journal:append $j [b] {actor: "u" authority: "g"}]]
[= $es [$journal:since $j 1]]
  [$journal:fold-value $es [?fn ($a $e) [+ $a 10]] 0]]
    
          20

    journal:temporal-slice

    [$journal:temporal-slice] -> [sequence element] — The PURE bitemporal projection over already-materialized entries (stream 8, the fold-value twin): opts {at-seq: N} cuts on the TX axis; {valid-at: T} engages the as-of collapse (in-cut :correction targets drop across their whole extent, :amendment clamps its target's valid-to to the amender's valid-from) then keeps the entries whose half-open [from, to) contains T. Entries without valid-time vocabulary are valid always; shredded entries pass through visibly.

          [?lib 'cx-stdlib/journal']
[?let [= $j [$journal:open "mem://bt-110" "acme"]]
[= $e1 [$journal:append $j [promo pct=10 valid-from="2026-08-01" valid-to="2026-08-05"] {actor: "u" authority: "g"}]]
[= $es [$journal:since $j 1]]
  [boundary at-from=[$count [$journal:temporal-slice $es {valid-at: "2026-08-01"}]] inside=[$count [$journal:temporal-slice $es {valid-at: "2026-08-04"}]] at-to=[$count [$journal:temporal-slice $es {valid-at: "2026-08-05"}]] before=[$count [$journal:temporal-slice $es {valid-at: "2026-07-31"}]]]]
    
          [boundary at-from=1 inside=1 at-to=0 before=0]

    journal:upcast

    [$journal:upcast] -> [sequence element] — The PURE upcaster seam over already-materialized entries (stream 21, the temporal-slice twin): applies a caller-supplied pure chain — an entry-to-entry projection — to every entry that carries an event payload. The chain's output supplies the payload only; the envelope is the journal's (rewriting seq= or hash= refuses CXER4642, dropping the payload refuses CXER4642). An entry the chain refuses is a loud CXER4641 naming seq, hash, and the declared schema — never absence, never a skip. Shredded entries pass through without chain application. The fold and replay opts take the same chain under {upcast: $chain}, composed BEFORE the valid-time projection.

          [?lib 'cx-stdlib/journal']
[?let [= $j [$journal:open "mem://se-118" "acme"]]
[= $e1 [$journal:append $j [order id="A-1" total=107 schema="sha2-256:a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1"] {actor: "svc" authority: "g"}]]
[= $e2 [$journal:append $j [order id="A-2" subtotal=90 tax=10 schema="sha2-256:b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2"] {actor: "svc" authority: "g"}]]
[= $up [?fn ($e)
  [?if [= $e/event/order/@schema "sha2-256:a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1"]
    [then [entry seq=$e@seq hash=$e@hash
      [event [order id=$e/event/order/@id subtotal=[- $e/event/order/@total 10] tax=10 schema="sha2-256:b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2"]]]]
    [else $e]]]]
  [upcast v2-subtotals=[$journal:fold $j [?fn ($a $e) [+ $a $e/event/order/@subtotal]] 0 "" {upcast: $up}] raw-v2-only=[$journal:fold $j [?fn ($a $e) [+ $a [$sum $e/event/order/@subtotal]]] 0] pure-count=[$count [$journal:upcast [$journal:since $j 1] $up]]]]
    
          [upcast v2-subtotals=187 raw-v2-only=90 pure-count=2]

    journal:lineage-path

    [$journal:lineage-path] -> [sequence element] — The lineage load (stream 21): validates a set of Lane-2 schema-lineage claims — each relating two schema content addresses under a closed relation set (:additive/:narrowing/:split/:merge) with an upcaster slot — FAIL-CLOSED: a duplicate edge, a cycle, or any pair of endpoints admitting two paths refuses CXER4643; then returns the claims along the UNIQUE from-to path in composition order. No covering path is the loud CXER4644 (lineage is directed). Same-endpoint queries return the empty (identity) chain.

          [?lib 'cx-stdlib/journal']
[?let [= $v1 "sha2-256:a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1a1"]
[= $v2 "sha2-256:b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2b2"]
[= $v3 "sha2-256:c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3c3"]
[= $c12 [schema-lineage [from $v1] [to $v2] [relation :additive] [upcaster "sha2-256:u12u12"]]]
[= $c23 [schema-lineage [from $v2] [to $v3] [relation :split] [upcaster "sha2-256:u23u23"]]]
[= $c13 [schema-lineage [from $v1] [to $v3] [relation :additive] [upcaster "sha2-256:u13u13"]]]
[= $path [$journal:lineage-path ($c12, $c23) $v1 $v3]]
[= $hops [$count $path]]
[= $ambig [?fallback [$journal:lineage-path ($c12, $c23, $c13) $v1 $v3] [recover-with [context] [code $err@code]]]]
[= $gap [?fallback [$journal:lineage-path ($c12,) $v2 $v1] [recover-with [context] [code $err@code]]]]
  [probe hops=$hops [rels [?splice $path/relation]] [ambig $ambig] [gap $gap]]]
    
          [probe hops=2 [rels [relation :additive] [relation :split]] [ambig [code 'cx-err:CXER4643']] [gap [code 'cx-err:CXER4644']]]

    journal:legal-holds

Returns [holds stream= head= count=] with one [hold seq= subject=|hash= signer= at=] per binding hold; opts {subject:|hash:} filter. head is the position the erase-subject precondition pins. The signature covers the claim's strict canonical text with the [sig] child removed; verification proves possession of key= — binding the key to the signer identity is authz/vc's domain.

    journal:erase-subject

    [$journal:erase-subject] -> element — The recorded RTBF command (stream 20): journal an attributed [erase-subject] record to the reserved per-tenant cx:erasure stream, then execute the crypto-shred walk — destroy the subject's SEK(s), tombstone every subject-sealed doc ([erased] with attribution), purge derived surfaces (computation cache, materialization checkpoints, in-process dedup records and plaintext caches), across the backing store and every store the segment index names. HOLD-BEATS-SHRED: a signed legal hold binding the subject (or a scoped hash) refuses CXER4621 atomically — the hold-stream head pins before commit and re-checks under the writing commit lock. The KMS destroy is strictly POST-COMMIT (the forward-only pivot). Idempotent: the journaled record IS the durable dedup record (its request= id is an opaque CSPRNG token); a resubmission answers [deduped ] and re-runs only the idempotent walk (self-heal). A committed shred advances the tenant shred-generation, staling every pre-shred snapshot's fold-id (CXER4640 on fold-from — re-snapshot is forced). Direct appends to cx:erasure refuse CXER4622. Returns the balanced [shred-report …]: docs = erased + already-erased.

[?lib 'cx-stdlib/crypto']
[?lib 'cx-stdlib/bytes']

    journal:verify

    [$journal:verify] -> element — Verify hash-chain integrity end to end, returning a [verification] finding (not an error on corruption). The chain verdict is syntactic — the entry hash covers the payload ADDRESS, so valid=true holds with payloads lawfully destroyed. On a valid walk every detached payload is fetched and re-hashed, and every missing payload reconciles against an ATTRIBUTED erasure record (a covering journaled shred-request, or the address's [erased] tombstone): the report gains redacted= payloads-verified= unattributed-missing= when the accounting engages, and any unattributed-missing > 0 is a LOUD finding — a payload gone with no lawful record is evidence of tampering or key loss, never silently counted among the redactions (stream 20).
