    Playground

    Sourcecx

    Browser-based libcx-wasm evaluator planned — see Concepts → WebAssembly Target for the transition plan. Until that ships, Run is disabled and the output panes carry pre-recorded canned results for each example. The Source pane is fully editable; use Reset to restore the canned source, or switch examples via the dropdown.

    How This Works

    The playground runs entirely in the browser. Pick a starter example from the dropdown, edit it in the Source pane, and the three output tabs underneath show the canonical CX form, the JSON projection, and the XML projection of the parsed tree. No server, no signup.

    Sixteen starter examples ship in the corpus today — seven CX shapes atom attributes sigils typed table anchor and merge mixed content multi-document and nine CXL snippets substitute ?for multi-branch ?if ?let filter pipeline named template CXPath axes and predicates cx:merge includes. Edit any of them in place; the Run button replays the example output today, and the v0.7.x WebAssembly build of libcx will route the same button through a live evaluator.

    Offline

    The browser playground is a static page. Clone the repo, render the doc tree with make docs, and serve _site/ from any HTTP server — the playground works without an internet connection. The example corpus, the TypeScript bundle, and the CSS all live under scripts/gen_docs/playground/.

    Syntax Highlighting

    Every code block on this site is syntax-highlighted by a tiny in-house JS module at scripts/gen_docs/highlight/. It speaks the languages the docs actually use — cx, cxl, shell, python, go, rust, javascript, typescript, java, c-sharp, ruby, kotlin, swift, v, sql, ebnf, xml, html, json, yaml, toml, md. The highlighter is regex-based, around 150 lines, no external library. The Playground panes use the same module on every Run.
