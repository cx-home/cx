# Migration: v0.6.0 → v0.7.0

The single-cut release that takes the cx evaluator from CXL 1.0 to
XQuery 4.0 / XPath 4.0 parity. Most v0.6.0 documents and programs
work unchanged; the breaking changes are narrowly scoped.

For the headline summary see
[`RELEASE_NOTES_v0.7.0.md`](../../RELEASE_NOTES_v0.7.0.md). This
guide is the operational checklist.

## TL;DR

```sh
# Run the migration tool on any tree that touches cx documents:
cx upgrade-config path/to/your-config/
```

The tool handles:

- `cxl-version="…"` → `cx-eval-version="…"` (the cx-directive
  attribute rename).
- Internal references to `spec/cxl.md` → `spec/eval.md`.
- Internal references to `examples/cxl/` → `examples/cx/`.

If you don't have programmatic config that names these paths, you
don't need the tool.

## Breaking changes (numbered for cross-reference)

### M1 — C ABI symbol rename

| Old symbol | New symbol |
|---|---|
| `cx_eval_cxl` | `cx_eval` |
| `cx_eval_cxl_with_len` | `cx_eval_with_len` |
| `cx_eval_cxl_streaming` | `cx_eval_streaming` |

**Action:** Update direct C-ABI consumers to the new names. The
v0.6.0 names remain exported as aliases for one transition release;
they will be removed in v0.8.0.

If you use the active binding wrappers (Python `cxlib.eval_cxl`,
Go `cxlib.EvalCXL`, Rust `cxlib::eval_cxl`, TypeScript
`evalCxl`), the rename is handled inside the binding and you do
not need to change call sites.

### M2 — `cxl-version` attribute → `cx-eval-version`

```cx
# v0.6.0
[?cx cxl-version=1.0]

# v0.7.0
[?cx cx-eval-version=4.0]
```

**Action:** Run `cx upgrade-config <path>` over any document tree
containing top-of-file `[?cx …]` directives, or edit by hand. The
old `cxl-version` attribute is accepted as a deprecated alias
during the v0.7.0 cycle; expect a deprecation warning in v0.7.x
and removal in v0.8.0.

### M3 — File/path renames

| Old path | New path |
|---|---|
| `spec/cxl.md` | `spec/eval.md` |
| `examples/cxl/` | `examples/cx/` |
| `conformance/cxl.txt` | `conformance/eval.txt` |

**Action:** Update markdown links, build scripts, or test runners
that reference these paths. The `.cxl` file extension is unchanged
(it remains a tooling-only convention).

### M4 — Active binding set narrowed

The conformance + test-corpus matrix narrows from nine bindings to
five:

| Active (v0.7.0) | Frozen (v0.7.0) |
|---|---|
| V (reference) | C# (moved to `lang/csharp/frozen/`) |
| Python | Java (moved to `lang/java/frozen/`) |
| Go | Kotlin (moved to `lang/kotlin/frozen/`) |
| Rust | Ruby (moved to `lang/ruby/frozen/`) |
| TypeScript | Swift (moved to `lang/swift/frozen/`) |

**Action:** Frozen bindings keep their v0.6.0 surface and continue
to work, but are not required to track v0.7.0 features. Plan binding
adoption accordingly. The original paths still exist (under a
`frozen/` substate per ADR 0022 §D4) so importer references like
`from cx-home/cx/lang/java/cxlib` continue to resolve.

### M5 — `cx_eval_streaming` W012 stub removed

If any program previously caught the W012 "not yet implemented"
error from `cx_eval_streaming`, that error path no longer fires —
streaming returns success and drives the write-callback per the
v0.7.0 contract.

**Action:** Remove W012-specific error handling. If your program
intentionally fell back to buffered eval when W012 fired, you can
either:

1. Use streaming directly now (it works).
2. Continue calling `cx_eval` if you don't want the streaming
   contract.

### M6 — ADR 0021 disambiguation

`spec/decisions/0021-cxdb-as-database-direction.md` → renamed to
`spec/decisions/0021-cx-database-direction.md`. Inside, "CXDB"
(the proposed engine direction) is now called "CX database" and
deferred to v1.0+. The `cxdb` / `.cxdb` binary file format (wire
byte `0x63`, shipped v0.6.0) keeps its name and is unchanged.

**Action:** Update any ADR links pointing at the old filename. If
your code uses `.cxdb` files (the binary format), nothing changes.

### M7 — `ref` element name reserved (strict at v0.7.0)

Per ADR 0003 D1 second bullet, the element name `ref` is reserved
in element-body position for the body-position reference form
`[ref @<Name>]`. v0.6.0 admitted non-conforming `[ref ...]` shapes
as regular elements for back-compat; v0.7.0 (GG12 row at
`spec/v0_7_0_status.md`) tightens to the spec text: any `[ref ...]`
that is NOT the exact `[ref @<Name>]` body-position form is a parse
error (`E207`).

Examples now rejected at v0.7.0:

```cx
[doc [ref note=hi]]            # E207 — `ref` with attrs
[doc [ref some text content]]   # E207 — `ref` with non-@id body
[doc [ref [child]]]             # E207 — `ref` with element children
```

The exact body-position form continues to parse and round-trips:

```cx
[doc
  [section #s-1 [title T]]
  [para See [ref @s-1] for context.]   # valid; lifts to body_ref
]
```

**Action:** Rename any non-conforming `[ref ...]` data elements to
a different element name (e.g., `[reference ...]`). The
`cx upgrade-config` migration tool (status row I1) provides
mechanical detection + fix for v0.6.0 → v0.7.0 migrations when it
ships; in the interim, a one-line `grep` over your source corpus
plus a sed/awk rename covers the common case.

`docs/migrations/v0.6-to-v0.7.md §M7` is the load-bearing reference
for the change. ADR 0003 D1 carries a 2026-05-18 amendment ratifying
the strict shift.

## Non-breaking additions (no migration needed)

The bulk of v0.7.0 is additive — full XQuery 4.0 expression
surface, CXPath axes, operator tokens, fn library, map/array
runtime values, streaming evaluator, `cx:lang` resolution, HTMX
example pattern, Parquet bridges in Python/Go/Rust. Existing
v0.6.0 programs run unchanged.

See [`RELEASE_NOTES_v0.7.0.md`](../../RELEASE_NOTES_v0.7.0.md)
"What's new — per row" for the full list, and
[`spec/v0_7_0_status.md`](../../spec/v0_7_0_status.md) for the
per-item authoritative state.

## Known carry-forwards from v0.6.0

These items remain partial / deferred at v0.7.0 — same as v0.6.0:

- Nested Arrow types (struct / list / dictionary-encoded /
  fixed-size-list / decimal) still error from the Arrow bridge
  with a clear "not yet supported" message. Scalar types continue
  to work cross-binding.
- TS Arrow / Parquet (W7 / X6) — deferred. Python / Go / Rust
  ship the bridges; TS lands in a future release once the Arrow
  IPC route stabilizes.
- Locale-sensitive fn library (Z3) — `format-number`,
  `format-date`, `compare`, `sort` do not yet honour `cx:lang`.
  The `Element.lang()` accessor is in place across all five active
  bindings; the wiring through the fn library is post-v0.7.0.

## Where to ask

- Spec questions: open an issue against [`cx-home/cx`](https://github.com/cx-home/cx).
- Migration tool bugs: tag with `migration` so
  `cx upgrade-config` maintainers can triage.
- Binding-specific questions: post in the per-binding README's
  questions section (e.g.,
  [`lang/python/cxlib/README.md`](../../lang/python/cxlib/README.md)).
