# Migrating to CX v0.7.0

This document is the canonical entry point for v0.7.0 migration.
See [`v0.6-to-v0.7.md`](v0.6-to-v0.7.md) for the per-row M1..M7
breaking-change matrix and step-by-step migration guidance.

## TL;DR

```sh
# Mechanical migration of v0.6.0 source to v0.7.0 conventions:
cx upgrade-config [--dry-run] [--lint-ref-elements] FILE...

# Examples:
cx upgrade-config --dry-run config.cx                  # preview changes
cx upgrade-config config.cx                            # apply changes
cx upgrade-config --lint-ref-elements docs/            # scan tree for M7
```

## Breaking changes summary

The tool handles:

| Row | What                                  | Auto-fixed |
|-----|---------------------------------------|------------|
| M1  | C ABI symbol renames                  | n/a (binding rebuild) |
| M2  | `cxl-version=` → `cx-eval-version=`   | ✅ |
| M3  | `spec/cxl.md` → `spec/eval.md`        | ✅ |
| M4  | Frozen binding set                    | n/a (build config) |
| M5  | `cx_eval_streaming` W012 stub removed | n/a (real impl shipped) |
| M6  | ADR 0021 file rename                  | n/a (link refs only) |
| M7  | `[ref ...]` strict reservation        | 🔎 lint only (intent ambiguous) |

For details on each row including the rationale + manual-fix
patterns for non-auto-fixable changes, see
[`v0.6-to-v0.7.md`](v0.6-to-v0.7.md).

## Idempotency

`cx upgrade-config` is idempotent: running it twice produces the
same output as running it once. The V test suite includes
`vcx/tests/upgrade_config_test.v` which exercises:

- Idempotent M2 rename
- Idempotent M3 path rewrite
- No-op on already-clean files

Run the suite via `make test-v` to verify the contract holds in
your build.

## Non-mechanical fixes

For M7 (strict `[ref ...]` reservation), the tool runs as a linter
when called with `--lint-ref-elements` because the rewrite intent
is ambiguous — depending on the author's data model, the right
fix is:

- Rename to `[reference ...]` (preserves attribute / body semantics)
- Wrap content in a non-reserved element name (`[citation ...]`,
  `[note ...]`, etc.)
- Restructure to use the body-position form `[ref @id]` (if the
  intent was a cross-document reference)

The lint output reports findings; authors apply the chosen fix
and re-run.
