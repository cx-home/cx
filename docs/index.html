CX — one language for your data and your code

TL;DR — reach for CX whenever the data is the point. One bracketed syntax is the document, the query, the program and the compiler's own tree, so the file you read is the file you transform, validate, hash, store and serve — with no second language in between.

We hold ourselves to a standard we can state in one line — readable on day one, batteries included, exact by default, and effects you grant rather than inherit — and we prove each term of it with a conformance case this page replayed when it was built:

  • a query is a pattern over the document, not code over an object model — program-for-003-name-email-pair;
  • a fraction literal is an exact decimal, and mixing one with a binary float is refused out loud rather than rounded in silence — ap-decimal-float-mix-right;
  • an error is a value that propagates out of whatever is built from it — no exception unwinds past you — program-construction-err-004-captured-err-propagates;
  • a program reads nothing it was not granted, and the denial is a value naming the flag that would allow it — io-001-read-file-cap-denied;
  • a regular expression cannot backtrack, so no input can make it run for as long as it likes — re-003-compile-backreference-unsupported;
  • state that outlives the program is two calls to a content-addressed store — store-rt-001-round-trip-get;
  • an agent-protocol message is an ordinary value projected to its wire form — mcp-001-call-tool-request-shape.

The installer resolves the latest release for your platform, checks its SHA-256 against the release's own checksum file and installs cx — or, where no prebuilt build exists, says so and points at the source build; cx primer then prints the manual for exactly the binary you installed. Every example on this page is a conformance fixture that was executed by cx 0.18.0-pre.1 when the page was generated, and the page is refused if one of them stops holding.

Two rings, and the groups above them

We build CX in two rings — Ring 0, the data format, which cannot execute anything, and Ring 1, the language — with the platform, the bindings and the ecosystem as groups above them. Imports point inward, never out, and the build enforces it. The figure is drawn from the module and repository registries when this page is generated, so it cannot drift from the tree it describes; the rings page reads it from the centre out, and the why page states our case in eight before/after panels.

Why reach for CX

The document and the program are the same shape

A query is a pattern over the document: "every user that has a name and an email". There is no object model to build first and no parser to call — the program reads the data in the form you wrote it.

input.cx

[users
  [user [name Alice] [email a@x.com]]
  [user [name Bob] [email b@x.com]]]

prog.cx

[?for [user [name $n] [email $e]]
       [yield [pair name=$n email=$e]]]
$ cx --data=input.cx prog.cx
[pair name=Alice email='a@x.com']
[pair name=Bob email='b@x.com']

Exact numbers are the default

A fraction literal is an exact base-10 decimal, and arithmetic keeps it one; mixing it with a binary float is refused out loud rather than rounded in silence — so money stays money.

prog.cx

[?let [= $subtotal 19.99] [= $shipping 5.01] [total [+ $subtotal $shipping]]]
$ cx prog.cx
[total 25.00]

Every format lands in one value model

JSON parses into the same values the language computes with: a map is a map, whichever format it arrived in.

prog.cx

[?lib 'cx-stdlib/json']
[$json:parse "{\"a\": 1}"]
$ cx prog.cx
{a: 1}

Typed tables are data, not a convention — the columns carry their types, which is what lets cx project a table to columnar formats without guessing:

input.cx

[users [table[name::string age::int active::bool]]
  alice 30 true
  bob 25 false
]
$ cx --from=cx --to=cx input.cx
[users [table[name::string age::int active::bool]]
  alice 30 true
  bob 25 false
]

Effects are granted, never inherited

A program reads nothing until you grant it, and a denial is an ordinary value that names the flag which would allow it:

prog.cx

[?lib 'cx-stdlib/io']
[$io:read-file "/var/log/app.log"]
$ cx prog.cx
[err code=cx-err:CXER0271 message='E_CAP_DENIED: read capability required for io-read-file; none granted (grant via --allow-read)']

Regular expressions that cannot blow up

Our re is RE2: linear time on any input, and the constructs that would need backtracking are refused when the pattern compiles, so no hostile string can turn a match into a denial of service.

prog.cx

[?lib 'cx-stdlib/re']
[$re:matches [$re:compile "a+"] "aaa"]
$ cx prog.cx
true

State that outlives the program is two calls away

The store is content-addressed: put-doc answers a handle derived from the document's canonical bytes and get-doc answers the document. mem:// needs no grant; a real URL talks to a served store with the same two calls.

prog.cx

[?lib 'cx-platform/store']
[?let [= $s [$store:open "mem://"]] [= $h [$store:put-doc $s [doc [item "hello"]]]] [$store:get-doc $s $h]]
$ cx prog.cx
[doc [item 'hello']]

Agent protocols are plain values

An MCP request is an ordinary CX value projected to its wire form — no bespoke serializer anywhere in the path.

prog.cx

[?lib 'cx-platform/mcp' :as mcp]
[?lib 'cx-stdlib/json' :as json]
[$json:emit [$mcp:call-tool-request 1 "get_weather" {location: "NYC"}]]
$ cx prog.cx
'{"id":1,"jsonrpc":"2.0","method":"tools/call","params":{"arguments":{"location":"NYC"},"name":"get_weather"}}'
