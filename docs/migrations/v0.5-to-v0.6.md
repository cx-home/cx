# Migrating from CX v0.5 to v0.6

This document is for users with existing v0.5 code, documents, or
binding-level integrations who are upgrading to v0.6.0. v0.6.0 is
the **API/format-stability boundary** — from v0.6.0 onward through
1.0, no breaking changes to the public surface (C ABI, binding APIs,
wire formats, spec-normative grammar).

The transition from v0.5 → v0.6.0 carries the closure of the 2026-05
binding audit (see the 2026-05 binding audit)
plus the three v0.6.0 ADRs landed mid-cycle:

- — collection literals + CXL refactor
- — Public Table API (17-member surface)
- — Analytics-bridge `cx table` CLI

It includes one BREAKING grammar change, one BREAKING binding API
behavior change, and a number of non-breaking additions you may want
to opt into. (Internal grammar revisions during the cycle — v3.3 →
v3.4 → v3.5 → v3.6 — are an implementation detail; users observe
only the v0.5 → v0.6.0 transition.)

If you only need a checklist, jump to [§4 Quick checklist](#4--quick-checklist).

---

## 1 — BREAKING: leading-zero integer literals

### What changed

Source like `02134` is no longer auto-typed as integer.

| Source | v3.3 result | v3.4 result |
| ------------ | -------------------- | -------------------- |
| `[zip 02134]`| `zip` body = `2134` (int) | `zip` body = `"02134"` (string) |
| `[year 0]` | `year` body = `0` | `year` body = `0` | (unchanged — bare `0` is fine)
| `[hex 0xFF]` | `hex` body = `255` | `hex` body = `255` | (unchanged — `0x` prefix exempts)
| `[code 007]` | `code` body = `7` | `code` body = `"007"`|

### Why

v3.3 silently dropped leading zeros, which corrupted ZIP codes,
zero-padded IDs, phone area codes, and other naturally-string-shaped
numerics. The v3.4 rule is mechanical and predictable: a bare token
that starts with `0` followed by another digit is a string. `0`
alone, `0.5`, and `0xFF` still parse as numerics.

### How to migrate your `.cx` files

If you have v3.3 documents that *intended* zero-padded numbers, do
nothing — they now round-trip as strings, which is what they were
all along. If you have v3.3 documents that *intended* dropped leading
zeros (i.e., you actually wanted `2134`), strip the leading zeros at
the source: `[zip 02134]` → `[zip 2134]`.

### Detecting affected documents

The repo's `cx canonical` command (when present in a release) flags
sources where v3.3 and v3.4 produce different ASTs. Until that
ships, the simplest detection is to grep for tokens matching
`/[ =\\[]0[0-9]+/` in your `.cx` corpus:

```sh
grep -rnE '[[ =]0[0-9]' your-docs/
```

A handful of false positives (e.g., `0.5` matches the regex) but
zero false negatives — anything affected will show up.

### How to migrate code that *parses* CX

If you wrote your own CX parser (rare — most users use libcx through
a binding), update the integer-literal rule per
`spec/grammar.ebnf` §[20c]: reject a leading `0` followed by another
digit.

If you use libcx through a binding, no code change is needed. The
`parse(cx_str)` family routes through libcx; the binding receives an
already-correct AST. Only your *input data* needs review.

## 2 — BREAKING: binding `loads()` / `dumps()` type fidelity

### What changed

In v3.3, `loads()` and `dumps()` round-tripped through JSON internally:

```
loads(cx_str): cx_str → cx_to_json → JSON.parse → native value
dumps(value): native value → JSON.stringify → cx_json_to_cx → cx_str
```

JSON's number type doesn't distinguish integer from float. The v3.3
round-trip silently coerced integers to floats. `dumps({"port": 8080})`
followed by `loads(...)` returned `{"port": 8080.0}`.

In v3.4, `loads()` / `dumps()` go through the new CXDB v1 binary
format directly (`cx_to_data_bin` / `cx_from_data_bin`). Type
fidelity is preserved: integers stay integer, floats stay float,
booleans stay boolean, bytes round-trip as bytes, dates round-trip
as the host's date type.

### Why this matters for your code

If your code asserted on the float-coerced output, those assertions
are now wrong:

```python
# v3.3 — passed
assert isinstance(loads(dumps({"port": 8080}))["port"], float)

# v3.4 — fails
assert isinstance(loads(dumps({"port": 8080}))["port"], int)
```

### How to migrate

**Recommended:** update assertions to use type-tolerant comparisons.
Most existing test suites already do this — they compare numeric
values (e.g., `== 8080` or `== 8080.0`, both pass) rather than types.
The v3.4 change just makes those tests pass for the right reason.

If you have type-strict assertions (`isinstance(..., float)` /
`is float64` / similar), update them to expect the source type.
Per-binding details:

| binding | v3.3 type for integer JSON values | v3.4 type |
| ---------- | ---------------------------------- | ---------------- |
| Python | `float` | `int` |
| Go | `float64` (via `encoding/json`) | `int64` |
| Rust | `Value::Number(Number::from_f64)` | `Value::Number(Number::from(i64))` |
| TypeScript | `number` (always) | `number` (Number.isInteger == true) or `bigint` if > 2^53 |
| Java | `Double` (via Gson default) | `Long` |
| Kotlin | `Double` | `Long` |
| Swift | `Double` (via JSONSerialization) | `Int64` |
| C# | `double` (via System.Text.Json) | `long` |
| Ruby | `Float` (via JSON.parse) | `Integer` |

### Other type-fidelity improvements

The v3.3→v3.4 jump also restores fidelity for:

- **Booleans**: stay `bool` in all bindings (some bindings previously
 coerced `false` to `0` via JSON).
- **null**: stays `nil` / `null` / `None` (not coerced to empty
 string in any binding).
- **bytes**: round-trip as native byte type (`bytes`, `[]byte`,
 `Vec<u8>`, `Buffer`, `byte[]`, `ByteArray`, `Data`, `byte[]`,
 binary-encoded `String` in Ruby) — v3.3 had no bytes round-trip.
- **datetime**: round-trips as native datetime type with full
 ISO 8601 source preserved.
- **map insertion order**: preserved in all bindings whose host map
 type preserves order (Python dict, JS Map, Java LinkedHashMap,
 Kotlin LinkedHashMap, Swift Dictionary*, C# Dictionary, Ruby Hash;
 Go map iteration order is intentionally randomized in the host
 language).

(* Swift Dictionary doesn't formally preserve insertion order, but
the round-trip semantically preserves keys; users needing ordered
iteration should sort.)

## 2.4 — Non-breaking: XML namespaces 

Phase 7.57–7.59 (2026-05-08). v3.4 adds XML-style scoped namespaces.
This is a strictly additive feature — documents written before v3.4
have no namespace declarations and continue to round-trip exactly as
before.

### What's new

- **`xmlns:prefix=URI` and `xmlns=URI` declarations** are recognized
 at parse time and resolved against the XML Namespaces 1.0 scope-
 stack model. Reserved prefixes: `xml:` →
 `http://www.w3.org/XML/1998/namespace`, `cx:` →
 `https://cx-home.org/ns/cx`. `xmlns=""` undeclares the default.
- **Expanded-name fields** on `Element` and `Attribute`: `local`
 (post-colon part of the source name) and `ns_uri` (resolved URI,
 or none for unbound / no-namespace cases). Source-form `name` is
 preserved verbatim for round-trip.
- **Per-binding accessors**: each of the 9 bindings (Python, Go,
 Rust, TypeScript, Java, Kotlin, Swift, C#, Ruby) ships
 `localName()` / `namespaceUri()` (or language-idiomatic spelling)
 on Element and Attribute. See per-binding namespace test for
 exact API.
- **CXPath namespace-aware predicates** ([`spec/cxpath.md`](../../spec/cxpath.md)
 §Namespace-aware queries): a query like `//svg:circle` resolves
 `svg:` against the document's xmlns map (first-occurrence wins;
 reserved `xml:` / `cx:` always available) and matches by expanded
 name. Two predicate functions cover cross-prefix cases:
 `local-name()` and `namespace-uri()`. Unbound query prefixes fall
 back to verbatim source-name match — back-compat for queries that
 use colon-bearing identifiers without namespacing intent.
- **Canonical form** ([`spec/canonical.md §2.7a`](../../spec/canonical.md)):
 `cx canonical` (and therefore `cx hash` / `cx eq`) emits xmlns
 declarations sorted (default first, then alphabetical by prefix)
 and rewrites prefix usage to the lex-smallest in-scope prefix per
 URI. Two semantically equal namespaced documents — same expanded
 names, different prefix choices — hash to the same value.

### What does NOT change

- The text grammar for plain elements and attributes is unchanged.
 An attribute `foo:bar=value` was already a valid CX attribute
 name; v3.4 just resolves it as a namespaced reference when an
 `xmlns:foo` declaration is in scope.
- Wire formats (`ast_bin`, `data_bin`) carry source `name`
 verbatim. Bindings re-resolve namespaces on load — no migration
 for existing wire-format consumers.
- `cx fmt` (lossless canonical) preserves source attribute order
 including xmlns declarations. The xmlns sort applies only to
 strict canonical (`cx canonical` / `cx hash`).
- `xml:lang` is still accepted as an alias for `cx:lang` on XML
 import per `spec/i18n.md`.

### What you may want to opt into

- If you produce or consume XML containing namespaced dialects
 (SVG, SOAP, MathML, Office Open XML, Atom, RSS, etc.) through
 CX, your CX source can now declare those namespaces explicitly
 for correct round-trip and explicit expanded-name access from
 application code.
- If you sign or content-address namespaced CX documents, the new
 canonical form gives you stable hashes regardless of prefix
 choice — you can edit a document to use a different prefix
 alias for the same URI without changing the hash.

### What's NOT changing (deliberate)

- `xml:space="preserve"` remains a non-feature — see
 .
- External entity references remain a non-feature — see
 .
- JSON / YAML / TOML / Markdown have no namespace concept; CX
 documents containing namespace declarations flatten prefixed
 names to the literal `prefix:local` string when emitted to those
 formats. The URI is lost on conversion. To re-namespace an
 imported CX document, add `xmlns:prefix=...` attributes
 explicitly. See [`spec/namespaces.md §4`](../../spec/namespaces.md)
 for the per-format conversion table.

## 2.5 — BREAKING: `:table` API field rename `columns` → `cols`

Phase 7.46 (2026-05-08). The `Table` API field that holds the
ordered column-name sequence is renamed from `columns` to `cols`.
The companion property `column_count` becomes `col_count`, and the
column-iterator method `iter_columns()` becomes `iter_cols()`.

Why: matches the V core's `TableData.cols` field and reads better
in the common access patterns (`t.cols.len`, `t.cols[0]`),
symmetric with `rows`. Done now while the Table API isn't yet
exposed in any binding's shipping API surface — the rename later
would touch every adopter's code.

What changes for adopters:

- **No source CX file changes required.** The grammar form
 `[name :table[col1:type col2:type ...]<rows>]` is unchanged. The
 rename is internal to the AST/binding-side `Table` type, not the
 text grammar.
- **AST consumers** (anyone reading `Element.table.cols` /
 `Element.table.col_count` / iterating `iter_cols()`) — rename
 `columns` → `cols`, `column_count` → `col_count`,
 `iter_columns` → `iter_cols`. The accessor `column(name)` is
 unchanged (it's the singular form, and refers to a column by name,
 not the field).

What does NOT change:

- The `:table` text grammar.
- The CXDB v1 binary wire format (the rename is field-name-level in
 the parser/AST, not the bytes).
- The `column(name)` accessor method.
- Conversion outputs (CSV, JSON arrays-of-objects, XML rows).

Migration note: per the readiness rubric §3, the Table API write
surface is still partial across bindings; most adopters are
consuming `loads()` output where the rename simply changes the
property name on the `Table` instance returned. Search for `.columns`
and `.column_count` in your binding's typed AST consumers and
rename to `.cols` and `.col_count`.

This is the last planned breaking change to the v3.4 API surface
before v0.6.0 locks the format and library API.

## 2.6 — Non-breaking: ID/IDREF cross-document references 

v3.4 adds `#id` declarations and `@id` references — a stable
cross-element identity mechanism distinct from the existing
anchor / alias / merge primitives (which remain merge-only,
intra-document only). Strictly additive; documents written
before v3.4 keep parsing, emitting, and converting exactly as
before. Spec at [`spec/identity.md`](../../spec/identity.md);
.

### What's new

```cx
# Declaration: `#name` at element-meta position (after element name,
# after &anchor / *merge, before :type and attributes).
[user #u-1 name=alice]

# Attribute-value reference: bare @name with no quotes.
[reviewer assigned-to=@u-1]

# Quoted '@literal' is a string, not a reference. The emitter quotes
# any string-valued attribute starting with @ to preserve the round-trip
# distinction.
[item label='@literal']

# Body-position reference: `[ref @id]` is a syntactic node form.
[para See [ref @section-3] for the rationale.]
```

The grammar additions are in [51] (ElementMeta now includes
`IdDecl`), the attribute-value production (bare-`@id` form), and
the body-position `[ref @id]` reserved-name form. ID names follow
the `Name` production minus `:` (reserved for namespace prefixes).

References resolve at parse time after include resolution
completes (when include resolution lands — currently document-
scope only). Forward references work; duplicate-IDs are a parse
error.

### Public API per binding

```python
# Python (idiom: snake_case, fields on Element/Attr)
elem.id # Optional[str]
attr.is_ref # bool
doc.resolve_id("u-1") # Optional[Element]
doc.elements_by_id() # dict[str, Element]
```

```go
// Go (idiom: PascalCase exported fields and methods)
elem.Id // string
attr.IsRef // bool
doc.ResolveID("u-1") // (Element, bool)
doc.ElementsByID() // map[string]Element
```

Equivalent shapes ship in Rust, TypeScript, Java, Kotlin, Swift,
C#, Ruby — see each binding's identity test for the exact spelling.

### C ABI surface (capability bit 20, libcx ≥ Phase 7.65)

```c
char* cx_id_lookup (const char* input, const char* id, char** err_out);
char* cx_resolve_ref(const char* input, const char* ref, char** err_out);
char* cx_node_id (const char* input, const char* cxpath, char** err_out);
```

`cx_id_lookup` returns the AST-JSON encoding of the matching
element (or empty for not-found); `cx_resolve_ref` is a vocabulary
alias following the declaration-vs-reference distinction;
`cx_node_id` returns the syntactic ID of the element selected by
the supplied CXPath (or empty when the matched element has no
ID). Bindings expose these as thin wrappers (`id_lookup` /
`IdLookup` etc.). Stateless — for repeated lookups against one
document, prefer the per-binding `resolve_id` / `elements_by_id`
accessors that go through the ast_bin Document model.

### Wire format change

The ast_bin format bumped 1 → 2 to carry the new `Element.id`
field and `Attribute.is_ref` flag verbatim across V↔binding
round-trip. Decoders accept v1 buffers as a no-op for the new
fields. Bindings rebuilt against libcx ≥ Phase 7.62 read v2
buffers natively.

### CXPath addition

```
//user[#u-1] # selects the user element with ID u-1
//[#u-1] # any element with that ID, anywhere
```

The existing `[@id="u-1"]` form continues to work for documents
using `id` as a user-data attribute; it matches an attribute, not
a syntactic ID. The two are independent.

### Strict canonical form

`cx canonical` rewrites IDs to a deterministic `id-N` naming
scheme in document order, and rewrites references to track
(per). Two documents that differ only in ID
*spelling* hash to the same value. Lossless `cx fmt` preserves
source spellings.

### XML round-trip

CX `#id` ↔ XML `xml:id="id"` (XML built-in URI namespace per
[`xml:id` 1.0 W3C Rec](https://www.w3.org/TR/xml-id/)).
`is_ref` attributes emit as plain `name="<id>"` on XML output;
on XML import, attributes whose value matches a declared `xml:id`
are reconstructed as `is_ref` attributes (best-effort lossless).

### v0 limitations

- Document-scope only. Include resolution itself doesn't merge
 ID spaces yet (separate roadmap row); the merging contract is
 specified in [`spec/identity.md §2.1`](../../spec/identity.md) so
 the eventual include resolver lands with a clear target.
- `Element.body_ref` (the body-position `[ref @id]` field) is
 V-core-only; ast_bin doesn't carry it yet, so per-binding
 Element types do not expose it. Bindings that round-trip text
 through V's parser/emitter preserve the construct intact.

### What does NOT change

- Anchors / aliases / merges (`&` / `*`) remain merge-only and
 intra-document. ID/IDREF is a parallel, distinct mechanism.
- User-data attributes named `id` (e.g. `[user id="u-1" ...]`)
 are NOT auto-promoted to syntactic IDs. Your existing
 `id="..."` data attributes keep their meaning.
- The CX ↔ XML / JSON / YAML / TOML / MD round-trip behavior on
 documents without `#id` / `@id` markers is unchanged.

## 2.7 — Non-breaking: Delimited conversion rewrite 

The framing of `spec/conversions.md §8` changed in 2026-05-08
(Phase 7.67).
The old §8 promised "lossless within `:table` scope" and rejected
non-tabular CX as an error. That promise was never honest — delimited
fields are inherently string-typed and type metadata can't be carried
in-band without breaking plain-CSV consumers (Excel, pandas,
BigQuery). The new §8 describes the conversion as **well-defined and
reasonable**, not lossless, and accepts non-tabular CX via shape
detection.

### What changed for CX → delimited (emit)

- **Non-`:table` CX now converts** instead of erroring. The emitter
 auto-detects shape:
 - `:table` block → declared columns drive output 1:1.
 - 2+ same-named child siblings under the root → repeated-row
 mode: each sibling is one row; columns are the union of attrs
 in first-occurrence order.
 - Otherwise → dotted-path mode: each leaf attribute becomes a
 column at `<child>.<...>.<attr>`; output is a single row.
 - Mixed (some repeated + some unique siblings) → error in v0.
- **Default line terminator is `\r\n`** (RFC 4180), not `\n`.
- **Arbitrary single-char delimiters** are accepted, not just
 `,` / `\t` / `|`. Any byte except `\r`, `\n`, `"`, `'`, `\\`.
- **Embedded `"` inside a quoted field is doubled** to `""` per
 RFC 4180 (was already true; now spelled out as a normative table).

### What changed for delimited → CX (parse)

- **Three quote styles accepted**: bare, `"..."` (with `""`
 doubling), `'...'` (with `''` doubling). v3.3 only accepted
 RFC 4180 double-quote.
- **Six universal escape sequences** in any field context (quoted
 or bare): `\\`, `\n`, `\t`, `\r`, `\"`, `\'`. Other `\X`
 sequences are a parse error (was: parse error before).
- **Empty unquoted cell → null**; empty quoted cell (`""` / `''`)
 → empty string. Previously the empty-cell-as-null distinction
 was implicit; it's now spelled out.
- **Per-column type narrowing**: when every value in a column
 auto-types to the same scalar type (with null not constraining),
 the emitted `:table` header annotates the column with that type.
 Previously every column was untyped on output.

### What didn't change

- The C ABI symbols `cx_to_csv` / `cx_from_csv` keep the existing
 short-name spelling and remain valid; their signatures are
 simpler now (no `delimiter` argument — the named alias is
 CSV-specific). The arbitrary-delimiter symbols
 `cx_to_delimited` / `cx_from_delimited` are new in this phase.
- Wire format for `:table` blocks is unchanged.
- The `to_csv()` / `from_csv()` host-binding API surfaces are
 unchanged in spec; the V core change is binding-invisible until
 the per-binding rollout phase.
- Use of `cx fmt` / `cx canonical` / `cx hash` is unchanged.

### When you have to do something

If your code:

- Generated CSV from a non-tabular CX file and was relying on the
 error → it now succeeds with shape-detected output. Add an
 explicit `:table` wrapper if you want a parse-time error
 instead of silent flattening.
- Parsed CSV with `\r` or `\n` row terminators expecting only
 `\n` → unchanged. Both are accepted as input; default emit is
 `\r\n` per RFC 4180 (pass `EmitOptions.line_ending = '\n'` to
 override).
- Parsed CSV with single-quoted fields expecting them to error →
 they now parse as quoted strings. If you want strict RFC 4180,
 pre-process input or wrap the parser.

### v0 limitations to know about

- Mixed shapes (some repeated + some unique siblings) error;
 tracked in ROADMAP.md "Later" if adopters surface a concrete
 need.
- Caller-supplied schema (per) is not yet wired to the
 V core path; will layer on with the schema validator .
 Until then, parse uses auto-typing → string-fallback.
- Arbitrary-delimiter callers compose `cx_to_delimited` /
 `cx_from_delimited` with `cx_to_data_bin` / `cx_from_data_bin`
 themselves; only the named-delimiter variants ship a
 `cx_<delim>_to_data_bin` one-shot.

## 2.8 — Non-breaking: CXDB analytics-bridge wire-format additions 

v0.6.0 promotes three previously-reserved tags to normative status
in `spec/data_bin.md`:

- **`0x63` — chunked tables** (`spec/data_bin.md §3.11`). A
 row-group-at-a-time table container; emitted by streaming-write
 consumers when the table doesn't fit in memory. Forward-decodable;
 byte-length-prefixed row groups; `0x00` terminator.
- **`0x90` — page-compression wrapper** (`spec/data_bin.md §3.12`).
 Wraps row-group bodies in zstd v1; `cx_hash` is computed over the
 decompressed canonical bytes, so compression level does **not**
 affect the file hash.
- **Header flag bit 1 — schema-driven encoding** (`spec/data_bin.md §3.13`).
 When set, the writer omits per-value type tags wherever the schema
 declares the type; the reader walks the schema in lockstep. A
 schema reference (`0x10` content-hash, `0x11` inline, or `0x12`
 hash + name hint) follows the 12-byte fixed header before the
 root value.

**This is additive.** Existing v0.6.0 self-describing CXDB documents
keep decoding identically. New documents that use any of the three
features are marked by their wire bytes (tag `0x63`, tag `0x90`, or
flag bit 1) and require a v0.6.0+ reader. v0.5.x readers that
encounter these documents reject at the unknown-tag / unknown-flag
check.

**What does NOT change.** Existing tag assignments (`0x60`, `0x62`,
all column type codes, all sentinel / numeric / temporal scalars)
are unchanged. The 12-byte fixed header layout is unchanged. The
canonicality rules for non-chunked tables are unchanged. `cx_hash`
on a self-describing document produces the same value before and
after this change.

**Capability bits.** `cx_features` adds bits 21 (chunked-table),
22 (page-compression), 23 (Apache Arrow C-Data interop, separate
`libcx_arrow` library), 24 (schema-driven encoding). Bindings query
the bits at load time and refuse to use unsupported capabilities.
Bit 17 (formerly tentative Arrow placeholder) is superseded by bit
23; see `spec/abi.md §3` for the reconciliation note.

**New C ABI surface.** The streaming Table reader / writer
(`cx_table_reader_*` / `cx_table_writer_*`, 10 symbols) and Arrow
bridge (`cx_arrow_export_*` / `cx_arrow_import_*`, 4 symbols in
`libcx_arrow`) ship with the v0.6.0 implementation phases following
this spec lock. Schema-driven entry points (`cx_to_data_bin_schema_driven`
and per-format variants) ship alongside.

**Phase 7.73 — schema-driven encoding V core landing.** The
schema-driven encoder / decoder (`emit_data_bin_schema_driven` /
`parse_data_bin_schema_driven` in V; ten new C ABI symbols
`cx_to_data_bin_schema_driven` + per-format variants for xml / json /
yaml / toml / md / csv / tsv / psv + `cx_from_data_bin_schema_driven`)
ship with this phase. Capability bit 24 (`0x1000000`) is set on
`cx_features`; the bitmask is now `0x17fffff` (bits 0–22 + 24).

The encoder takes the source document plus a `.cxs` schema text,
parses both, and emits CXDB framed bytes with header flag bit 1 set
and the schema reference embedded in one of three forms (default
`0x10` content-hash; `0x11` inline schema; `0x12` content-hash +
UTF-8 name hint). Tag-omission is **per-field**: declared keys get
typed-payload-only encoding, undeclared keys (under the default
`open` mode D6) fall back to self-describing CXDB.
`closed` mode rejects undeclared attrs at emit time with `S012`;
`strict` mode is reserved for v0.7+. Encoding and validation are
**decoupled** D3 — emitting schema-driven bytes does
not run schema validation, and having a schema in scope does not
auto-promote the encoder; the schema-driven flag is an explicit
opt-in via the `cx_to_data_bin_schema_driven` entry points.

The schema content-hash is computed as
`SHA-256(cx_to_data_bin(parse(schema_text), strict_canonical))` per
 D5; comments and whitespace in the `.cxs` source do not
affect the hash because the parse → emit_data_bin pipeline already
strips them. The decoder reverses the encoding by walking the
schema's type-declaration tree in lockstep with the data; declared
keys get typed-payload-only reads, undeclared keys get
self-describing reads.

This phase also extends the `[?cx ...]` directive grammar to accept
positional bare-token arguments alongside the existing `key=value`
form. The text `[?cx schema-of server]` and `[?cx schema-mode open]`
now parse uniformly with `[?cx schema=path]` and
`[?cx lint-disable=L001]`. Existing `key=value` directives are
unchanged; bare-token positional args are simply additive. The
emitter mirrors this — empty-value attrs round-trip as bare tokens
without an `=` suffix.

**Phase 7.72 — chunked-table V core landing.** The chunked-table writer / reader
(`emit_data_bin_chunked` / `read_chunked_table_payload` in V; one new
C ABI export `cx_to_data_bin_chunked`) ship with this phase. Default
chunk policy is **2²⁰ rows per group** (the strict-canonical chunk
size D1, configurable via `ChunkedEmitOptions.chunk_size`).
Page-compression is **auto** by default — a row-group body ≥ 64 KiB
gets wrapped in a zstd v1 frame at level **3** (zstd's own default,
adjustable via `ChunkedEmitOptions.compress_level`); smaller bodies
emit plain. Adopters with explicit policy needs choose `compress: .never`
or `compress: .always`. zstd is consumed via V's stdlib
(`compress.zstd`); no devbox or downstream-binding-side dependency
change is required. `cx_to_data_bin` itself continues to emit `0x60`
for in-memory tables (default behavior unchanged); `0x63` is the

**Phase 7.74a — streaming Table reader / writer V core + 10 C ABI
symbols.** The 10-symbol streaming Table surface declared
0015 D8 / `spec/abi.md §2.10` ships with this phase:

```
cx_table_reader_open / cx_table_reader_open_fd /
cx_table_reader_schema / cx_table_reader_next /
cx_table_reader_close

cx_table_writer_open / cx_table_writer_open_fd /
cx_table_writer_emit_row_group / cx_table_writer_close_get_bytes /
cx_table_writer_close
```

The reader pulls one row group at a time (transparently decompressing
`0x90` zstd-wrapped bodies); the writer pushes one row group at a
time (auto-compressing bodies above 64 KiB by default per the
existing `ChunkedEmitOptions` policy). Memory use is bounded by the
largest single row group plus a constant overhead.

**Wire-format conventions.** In-memory variants (`*_open`) consume /
produce the framed `[u32 LE size][CXDB payload]` form used elsewhere
in this ABI. Fd variants (`*_open_fd`) operate on **bare CXDB bytes**
without the 4-byte framing prefix, since a streaming writer cannot
prefix its output with a size unknown until end-of-table; the file's
length is implicit from the fd. Readers mirror this so a writer's
output is directly consumable by a reader. The two conventions are
intentionally distinct: callers must not feed framed bytes through
`*_open_fd` or vice-versa.

**Col-spec exchange.** `cx_table_reader_schema` returns the table's
columns as a framed ast_bin buffer: a single root Element named
`table` with one Attribute per column, where the attribute name is
the column name and its value is the column's type name (`'string'`,
`'i32'`, `'i64'`, `'float'`, `'bool'`, `'date'`, `'datetime'`,
`'bytes'`, or `''` for the default-string column). The writer
consumes the same ast_bin shape on `*_open`. Bindings can introspect
the schema before the first row-group read.

**Row-group payload format.** `cx_table_reader_next` returns the
next row group as a framed `[u32 LE size][plain body]` buffer where
`<plain body>` is the §3.11.2 plain-body form (uvarint(row_count) +
column-major col-payloads, no body-tag). On end-of-table the symbol
returns NULL with `*err_out` unset. `cx_table_writer_emit_row_group`
takes the same framed plain-body form and chooses the on-wire
body-tag (`0x01` plain or `0x90` zstd) per the writer's options.
The plain-body convention keeps bindings codec-agnostic — they
emit and consume row groups in their decompressed canonical form
and let the V core handle compression policy.

**Memory ownership.** Returned `char*` buffers are heap-allocated;
caller frees with `cx_free`. Reader / writer handles are class **H**
(thread-local) per `spec/abi.md §1.5.1`; bindings must not share a
handle across threads. `cx_table_reader_close` /
`cx_table_writer_close` release the handle; the V GC reclaims the
backing struct. The reader does NOT close its fd; the writer DOES
flush an end-of-table marker on close (fd mode) but does NOT close
the fd. Caller owns fd lifetime in both cases.

**Capability bit 21** (`0x200000`) signals reader / writer support;
already set on this build (Phase 7.72 reserved the bit when
the chunked-table format itself landed; Phase 7.74a fills out the
streaming surface under the same bit). Phase 7.74b ships per-binding
wrappers (Python context manager, Go `defer Close()`, Rust RAII /
`Drop`, TypeScript async iterator, etc.) following the established
9-binding pattern.

**Conformance impact.** Three previously-skipped fixtures unblock
this phase: `ch-004` (chunked-vs-plain produce distinct canonical
bytes), `cmp-003` (D005 unknown-codec rejection), `cmp-004` (D006
codec-id-zero canonical-form rejection). Remaining `cmp-001` /
`cmp-002` / `cmp-005` / `ch-005` defer to later sub-phases pending
cx_hash compression-invariance, mixed-codec writer policy, RSS-
snapshot harness infrastructure, and 1M+ row corpus synthesis
respectively.

**No source-code migration is required.** Adopters who don't reach
for chunked tables, compressed CXDB, or schema-driven encoding see
no behavior change from this addition. Adopters who *do* want these
features opt in explicitly: `cx fmt --schema-driven`, the streaming
Table API, or the `cx table` subcommand once it lands.

**V impl notes worth carrying forward:**

- **Module-level mutable state needs `-enable-globals`.** The lib-arrow
 Makefile target sets the flag because the export/import pipeline
 uses a `__global` token-keyed registry to keep V GC roots alive
 for ExportState and per-row-group LiveArrayBuffers — the Arrow
 C-Data structs hold V pointers via `private_data`, and V's GC
 doesn't scan caller-allocated C structs.
- **`struct C.X` fields need a C header.** V doesn't emit struct
 bodies for `struct C.*` references; the file

- **Reference-field-required-on-init.** V refuses `C.ArrowArray{}`
 short-init for structs containing reference fields (`children`,
 `dictionary`, `buffers`). The pattern that compiles is
 `unsafe { malloc(int(sizeof(C.ArrowArray))) }` followed by
 `vmemset(..., 0, sz)` and a cast to `&C.ArrowArray`.

```go
 alice 91
 bob 88]`)

for reader.Next() { _ = reader.Record() } // []arrow.Record streamed

 {Name: "name", Type: arrow.BinaryTypes.String},
 {Name: "score", Type: arrow.PrimitiveTypes.Int64},
}, nil)

defer bld.Release()

bld.Field(1).(*array.Int64Builder).AppendValues([]int64{91}, nil)
rec := bld.NewRecord()
defer rec.Release()
rdr, _ := array.NewRecordReader(schema, []arrow.Record{rec})
out, _ := cxlib.ArrowImportToDataBin(rdr) // unframed CXDB bytes
```

**Phase 7.74c-datetime-foundations — strict-cell datetime wire form
(2026-05-09).** Pure V core change — no binding work in this phase.
Replaces the prior `data_bin.v::encode_datetime` placeholder
(8 bytes ns + 2 bytes offset + 2 bytes reserved + raw source) with
the 12-byte strict-canonical form per
[`spec/data_bin.md §3.6.1`](../../spec/data_bin.md): i64 unix_nanos LE +
i16 offset_minutes LE (always 0 in canonical) + u16 reserved (zero).
The chunked-table strict-cell encoder
([`vcx/cx/data_bin_chunked.v::encode_strict_cell`](../../vcx/cx/data_bin_chunked.v)
/ `read_strict_cell`) gains the `tag_datetime` case using the same
12 bytes per row, mirroring the `tag_date` precedent. New parser
helpers `cx.parse_iso_datetime_canonical(s) → (i64, i16)` and
`cx.format_iso_datetime_utc(ns, offset_min) → string` are exported
from the cx module — both pub for downstream tooling.

ISO-8601 grammar accepted: `YYYY-MM-DDTHH:MM:SS[.<frac>][Z|±HH:MM]`.
Fractional seconds beyond 9 digits truncate to ns precision; naive
datetimes (no Z / offset) are treated as UTC; leap seconds and
out-of-i64-ns range (~year 1677..2262) are rejected at encode time.
Strict canonical wire form normalizes to UTC (offset_minutes = 0
on the wire); the parser preserves the source offset only for
diagnostic purposes. Round-trip output uses canonical form
`YYYY-MM-DDTHH:MM:SSZ` (with `.<frac>` if non-zero, trailing zeros
trimmed).

**Phase 7.74c-abi-c-test — C-level ABI conformance test (2026-05-10).**
A small C harness at `tests/abi/c_abi_test.c` exercises the boundary
surface where binding-runtime bugs have actually surfaced: chunked
emit (`cx_to_data_bin_chunked`), the streaming Table reader / writer
(`cx_table_reader_open` / `_schema` / `_next` / `_close`,
`cx_table_writer_open` / `_emit_row_group` / `_close_get_bytes` /
`_close`), and the libcx_arrow surface (`cx_arrow_features`,
`cx_arrow_version`, `cx_arrow_export_open`,
`cx_arrow_import_to_data_bin`, `cx_arrow_free`) — ≈12 symbols total.
Compiled under `-fsanitize=undefined -g -O1` (UBSan-only by default;
see Sanitizer choice below) and run via the new `make abi-c-test`
target (also wired into `make test`):

```bash
make abi-c-test # default: UBSan only
ABI_C_TEST_SAN=address,undefined make abi-c-test # opt back into ASan
```

Coverage shape: each tested symbol gets at least one valid call
asserting expected output, plus (where the ABI declares NULL-safety or
explicit input rejection) one invalid-input call asserting the error
path doesn't leak or double-free under the sanitizers. libcx is
linked at compile time; libcx_arrow is `dlopen`'d at runtime with
`RTLD_NOW | RTLD_LOCAL`, mirroring how bindings actually load it (the
JNA / cgo / dotnet boundary is where the Arrow rollout's bugs
surfaced).

Why this matters under the v0.6.0 binding tiering model. Per
`spec/parity_matrix.md` and the binding-tier framing decided
2026-05-09, Tier 3 bindings (Kotlin / Swift / Ruby / TS / V cffi)
defer their Arrow rollout to post-v0.6.0. The C ABI test substitutes
for the gap-finding value the missing binding rollouts would have
provided — most of what multi-binding revealed surfaced via
`dlopen`-level memory shape, which a C test catches at source. It
does NOT cover binding-runtime-specific issues (JNA allocator quirks,
cgo cross-thread lifetimes, dotnet GC pinning, Java size-header
endian-flip) — those still need binding-level tests when the affected
binding lights up.

Sanitizer choice. The target uses UBSan only by default
(`ABI_C_TEST_SAN=undefined`). Apple clang 21's AddressSanitizer
runtime on macOS 26 (Tahoe) deadlocks deterministically inside
`__asan::AsanInitInternal` — `__malloc_init` calls
`wrap_malloc_default_zone` which re-enters `AsanInitFromRtl` before
init completes, and the runtime spins forever in
`StaticSpinMutex::LockSlow` yielding the CPU through `swtch_pri`.
The bug is independent of the nano-malloc zone (`MallocNanoZone=0`
does not avoid it). UBSan alone reliably catches the integer-overflow,
NULL-deref, and out-of-bounds-load classes the boundary surface is
most likely to expose; loss versus ASan is heap-use-after-free,
double-free, and heap-buffer-overflow writes — risks that exist
mostly inside libcx, not on the boundary the harness tests.

To opt back into full ASan + UBSan when running on Linux or with a
newer clang (e.g. Homebrew LLVM whose ASan runtime has been
patched), invoke `ABI_C_TEST_SAN=address,undefined make abi-c-test`.

A future expansion to full `cx.h` coverage (the AST-bin symmetric
surface, CXPath, ID/IDREF, schema-driven encoding) is multi-session
and stays out of v1 scope.

## 2.9 — Non-breaking: collection literals 

CX gets three first-class literal forms for collections, all
round-tripping across CX text, JSON, YAML, TOML, MD, XML, CXDB, and
AST-bin.

### What's new

| Literal | Surface | Type | Example |
| --- | --- | --- | --- |
| Sequence | `(a, b, c)` | `seq[T]` (flattens into containing context) | `[tags (admin, user)]` |
| Array | `[a, b, c,]` | `arr[T]` (ordered, indexed; trailing comma disambiguates) | `[ports [8080, 8081, 8082,]]` |
| Map | `{k: v, ...}` | `map[K, V]` (string-keyed at v0.6.0) | `[hosts {alice: 1.1.1.1, bob: 2.2.2.2}]` |

Schema annotations: `arr[T]`, `seq[T]`, `map[K, V]` are accepted in
`:table` column headers and `:type` directives.

### What does NOT change

No source from v3.4 breaks. The new forms slot into positions that
previously errored (e.g., bare `{...}` in body position). Existing
single-element arrays still need a trailing comma to be unambiguous:
`[user,]` is array, `[user]` is element-call.

### CXL surface ( §D23–D25 + )

Labeled-form directives — `[?if cond :then a :else b]` — landed
alongside positional. Body labels and kebab-case FLWOR keywords
(`order`, `where`, `for`) replace the older `order-by`. Parameterized
templates: `?def name :params [a b] :body ...` with `dispatch_template_call` doing the lexical-scope expansion.

### Why

Three pain points solved at once: column cells couldn't carry
collection-typed data without escape hatching through XML or JSON;
schema layer had no way to express `arr[int]`; CXL templates had a
readability cliff above three arguments.

## 2.10 — Non-breaking: Public Table API 

`:table` blocks are now first-class via the **17-member canonical
Table API** in every binding. Stable through v1.0.

### What's new

```python
import cx
t = cx.Table.from_cx(open('data.cx').read())
print(t.row_count, t.cols) # 100, ['name', 'age', 'city']
for row in t: # iteration
 print(row['name'], row['age'])
print(t.column('age')) # column by name
sliced = t.slice(0, 10).select_cols(['name']) # methods chain
print(sliced.to_csv(delim=','))
```

```go
t, _ := cxlib.TableFromCx(src)
for _, row := range t.Rows() {
 fmt.Println(row["name"], row["age"])
}
```

```rust
let t = cxlib::Table::from_cx(src)?;
let view = t.select_cols(&["name", "age"])?.head(10);
println!("{}", view.to_json());
```

### Surface (canonical)

| Members | Names (per-binding naming follows local convention) |
| --- | --- |
| Properties (4) | `cols`, `types`, `row_count`, `col_count` |
| Access (9) | `row`, `column`, `col_at`, `cell`, `cell_by_name`, `slice`, `head`, `tail`, `select_cols` |
| Iteration (2) | `__iter__` / `each` / `for-of`; `iter_cols` |
| Conversion (5) | `to_cx`, `to_csv(delim=',')`, `to_json`, `to_data_bin`, `to_dict_list` |
| Equality | `equals` / `==` (recursive cell equality) |

Construction: `from_cx(src)` / `from_cx_all(src)` / `create(cols, types, rows)`.
The `create` factory enforces 4 invariants ( §D7): cols-types
len match, unique cols, row-shape uniform, types accepted.

### What does NOT change

`StreamingTable` (Phase 7.72+) is unchanged — it's the chunked-table
streaming reader/writer for very large tables. Table API is the
in-memory eager surface; StreamingTable is the chunk-by-chunk
streaming surface. Use Table API for ≤ 2²⁰ rows; StreamingTable
for analytics-scale.

### `select` → `select_cols` rename

Across all bindings, the canonical `select` member is exposed as
`select_cols`. This is uniform regardless of language; some bindings
(Ruby with `Enumerable#select`; .NET with LINQ `Select`) would have
clobber issues, so the rename is global for consistency.

## 2.11 — Non-breaking: `cx table` CLI subcommand ( §D1)

The `cx` CLI grows a `table` subcommand for inspect / round-trip /
(Phase C) Parquet / Arrow IPC export.

### Verbs available at v0.6.0 RC

```sh
$ cx table info FILE.cx # column count, row count, types, byte size
$ cx table dump FILE.cx --to=cx > out.cx # round-trip via Table API
$ cx table load FILE.cx --to=cx > out.cx # symmetric inverse
```

### Verbs reserved for Phase C (post-v0.6.0)

```sh
$ cx table dump FILE.cx --to=parquet > out.parquet
# cx table dump --to=parquet: binding does not ship Parquet/Arrow
# adapter at v0.6.0 RC — defers to libcx_arrow Phase C ( §D4)
```

`--to=parquet` and `--to=arrow` exit 3 with the message above
at v0.6.0; the surface is reserved and forward-compatible.

### What does NOT change

No new C ABI symbols. `cx table` is a pure-CLI composition over
`cx.tables_from_cx` + `cx.Table.to_cx` (and, when Phase C lands,
`libcx_arrow_*`). Per §D7, `spec/abi.md` doesn't grow at
v0.6.0 for this feature.

## 3 — Non-breaking additions you may want to opt into

These don't break v3.3 sources but are new tools v3.4 makes
available.

### 3.1 New scalar types (sized + decimal + bigint)

Type annotations now include sized variants and arbitrary-precision
forms:

```cx
[port:u16 8080]
[temp:f32 98.6]
[balance:decimal 1234567890.123456]
[fingerprint:bigint 340282366920938463463374607431768211456]
```

Use these when the default `int` (i64) or `float` (f64) lose
precision or signal width is part of your data contract. See
`spec/type_mapping.md` for the host-type mapping per binding.

### 3.2 `:table` blocks

Wide-table data now has a first-class form:

```cx
[stocks :table
 [columns ticker:string price:f64 volume:u32]
 [rows
 AAPL 192.45 38291092
 GOOG 142.30 18234567
 MSFT 415.18 23456789
 ]
]
```

The CX text form is row-major; the binary form (`cx_to_data_bin`) is
column-major with per-column compact encoding (bit-packed booleans,
delta-encoded ints). For datasets larger than ~10K rows, `:table` is
~5-10× smaller than equivalent `[stock ticker=AAPL ...]` element
form. See `spec/table_api.md`.

### 3.3 Numeric underscores

Underscores between digits are now readability aids and stripped at
parse time:

```cx
[max_int 9_223_372_036_854_775_807]
[hex 0xCAFE_BABE]
[ratio 3.141_592_653]
```

### 3.4 Boolean attribute sigils

Compact form for boolean attributes:

```cx
[user +admin -disabled name=alice]
# equivalent to: [user admin=true disabled=false name=alice]
```

### 3.5 Line comments

`#` to end-of-line is now a comment:

```cx
[config
 [host localhost] # development default
 [port 8080] # changed from 80 to avoid root
]
```

This is *in addition to* the v3.3 block comment form `[- comment ]`.
Both work. Line comments are stripped at parse time — they don't
appear in the AST or any output format.

### 3.6 logfmt mode

A document may consist of top-level `key=value` attributes (the
[logfmt](https://brandur.org/logfmt) convention):

```cx
ts=2026-05-07T10:30:00Z level=info service=api request_id=abc123 latency_ms=45
```

Loaders interpret these as a single synthetic Element with the
attrs attached. Useful for log streams. See `spec/grammar.ebnf` §[2].

### 3.7 Triple-quoted string delimiter

For multi-line strings without escaping:

```cx
[doc :string
 '''
 Line one
 Line two with "quotes" and \backslashes
 Line three
 '''
]
```

### 3.8 Streaming with handle-based pull

Bindings now expose a true pull-based streaming API in addition to
the legacy eager-buffered `stream(cx_str) -> List<Event>` form.

| binding | new API |
| ---------- | ---------------------------------------------------- |
| Python | `cxlib.Stream(cx_str)` (was eager; now handle-based) |
| Go | `cxlib.OpenEvents(cx_str) -> *EventStream` |
| Rust | `cxlib::EventStream::open(cx_str)?` |
| TypeScript | `openEvents(cxStr) -> EventStream` (Iterable) |
| Java | `EventStream.open(cxStr)` (try-with-resources) |
| Kotlin | `EventStream.open(cxStr)` (use {} block) |
| Swift | `EventStream(cxStr)` |
| C# | `EventStream.Open(cxStr)` (using statement) |
| Ruby | `CXLib::EventStream.new(cx_str)` (Enumerable) |

The legacy `stream(cx_str) -> List` shape still works in every
binding. Use the new form only if you care about memory: large inputs
no longer materialize all events up front.

### 3.9 CXPath in C ABI

If you were maintaining a non-V binding that re-implemented CXPath in
its host language, you can delete that code now. See
`spec/abi.md` §2.7 for the `cx_select_all_paths` symbol. The
in-tree bindings deleted ~3970 LOC of duplication this way; your
custom binding should be similar.

## 4 — Quick checklist

For most users:

- [ ] Grep your `.cx` files for leading-zero integers (§1). Decide
 per-document: did you mean string (no change) or integer
 (strip the zero).
- [ ] If you have type-strict assertions on `loads()`/`dumps()`
 output, update to expect the source type per §2's table.
- [ ] If you use the streaming API on large inputs and care about
 memory, switch to the new pull-based form (§3.8).
- [ ] *Optional:* adopt `:table`, sized types, numeric underscores,
 bool sigils, line comments, or logfmt where they reduce
 verbosity in your sources.

For binding maintainers (third-party):

- [ ] Update your binding to call `cx_ast_bin_to_<fmt>` for
 `Document.to_<fmt>` instead of round-tripping through CX
 text. (Closes CB-1; see `spec/abi.md` §2.3.)
- [ ] Update your binding to call `cx_<fmt>_to_ast_bin` for
 `parse_<fmt>` instead of going through `cx_<fmt>_to_ast` +
 JSON parse. (Closes CB-2; see `spec/abi.md` §2.3.)
- [ ] Update your binding to call `cx_to_data_bin` /
 `cx_from_data_bin` for `loads` / `dumps` instead of going
 through `cx_to_json` / `cx_json_to_cx`. (Closes CB-3; see
 `spec/abi.md` §2.4.)
- [ ] Update your binding to call `cx_events_open` /
 `cx_events_next` / `cx_events_close` for `stream()` instead
 of `cx_to_events_bin`. (Closes CB-4; see `spec/abi.md` §2.8.)
- [ ] Delete your local CXPath parser and route through
 `cx_select_all_paths`. (Closes CB-5; see `spec/abi.md` §2.7.)

The 9 in-tree bindings completed this checklist in branch
`native-data-binding`; their commits are referenced in
`the 2026-05 binding audit` and serve as templates. Python is the
canonical reference (smallest, most idiomatic).
