50 Ways to Love Your CX Data

Fifty short CX data examples, simple to complex. Pizzeria edition.

Read This First

Fifty examples that walk through CX data — bare attributes through anchors and merge, with stops at quoted strings, multi-line text, comments, collection literals, typed columns, and a final whole-shop document. Each step adds one shape; no shape requires anything the earlier ones do not already give you. The companion 50 Ways to Love Your CXL Code covers CXL directives.

1. The Atom

Just name equals value. In CX this is a valid document on its own — logfmt mode, intended for log lines and structured events.

cxsize=large

2. Several Atoms — a One-Line Event

A whole log line — no brackets, no root, just attributes.

cxtime=2026-05-09T12:00:00Z level=INFO svc=oven pizza=Margherita

3. Empty Element

Brackets give a name. Empty, but a thing.

cx[pizza]

4. Element With One Property

The atom from example 1, now attached to a pizza.

cx[pizza size=large]

5. Several Properties

Keep adding. No commas required between attrs.

cx[pizza size=large crust=thin price=12]

6. Bare Flag (No Equals-Value)

Presence means yes, absence means no — same idea as --verbose or HTMLs required. Here, this pizza is controversial.

cx[pizza name=Hawaiian controversial]

7. Explicit Boolean Values

When you want both polarities, write the word.

cx[pizza vegan=true gluten-free=false]

8. Boolean Sigil Shorthand

Plus-name means name=true; minus-name means name=false. Compact form for many booleans.

cx[pizza +vegan -nuts -gluten]

9. Numbers — Int, Decimal, Negative, Hex, Underscores

All bare, all auto-typed. Underscores in numbers are readability sugar.

cx[pizza price=12.50 discount=-2 ovens=4 mask=0xFF00FF batch=1_000_000]

10. Quoted — Single Quotes

Reads: attribute name, value is the string BBQ Chicken.

cx[pizza name='BBQ Chicken']

11. Quoted — Double Quotes

Pick the quote that does not appear in the value.

cx[pizza name="Quattro Formaggi"]

12. Mix When the Value Has an Apostrophe

Double-quote around an apostrophe; no escaping needed.

cx[pizza name="Tonys Special"]

13. The Empty String

Distinct from missing: the attribute is there, just empty.

cx[pizza name=Mystery description=""]

14. Escape Sequences Inside Quotes

Same family as C and JSON: backslash-n, backslash-r, backslash-t, backslash-uXXXX, backslash-quote, backslash-backslash.

cx[pizza alert='Hot!\\nHandle with care.\\tCafe e']

15. Entity References (XML-Style)

Ampersand-amp-semicolon, ampersand-lt-semicolon, ampersand-gt-semicolon work as in XML. Useful when a literal ampersand would confuse the parser.

cx[pizza name='Cheese &amp; Pepper' note='use &lt;tongs&gt;']

16. Null

A real null value, distinct from empty string or the word null as a string.

cx[pizza discount=null reviewed=null]

17. Date and Datetime Literals

ISO 8601 shapes are auto-typed as date or datetime.

cx[promo starts=2026-05-01 ends=2026-05-31 cutoff=2026-05-31T23:59:00Z]

18. Plain Text Body

After the name, the rest of the bracket is text.

cx[motto Hand-tossed since 1987]

19. Attributes Plus Text Body

Reads: element pizza, attribute name=Margherita, then text body Classic since day one.

cx[pizza name=Margherita Classic since day one.]

20. Multi-Line Text — Preserved as Written

Whitespace and newlines inside a text body are kept literally.

cx[description
  Stone-baked, hand-stretched,
  and ready in 90 seconds.]

21. Triple-Quoted String

Three quotes open and close. Single and double quotes inside need no escaping. Common leading whitespace is stripped.

cx[bio Born in Naples, 1955. Started Pepes in 1987. Still on the line every Friday.]

22. Block Content [| … ]

Like a text body, but indentation and newlines are kept verbatim. Unlike triple-quoted, inner elements such as best are still real markup.

cx[poem [|
  Roses are red,
    violets are blue,
  the [em best] pizza
    is waiting for you.
]]

23. Raw Text [# … #]

The CDATA of CX. Brackets, quotes, less-than, greater-than — all literal characters. The terminator is hash-bracket.

cx[snippet [# if (x < 10) { return "[pizza]"; } #]]

24. Embedded Code in Another Language

Raw text is how you embed SQL, JS, or regex without escaping every quote.

cx[query language=sql [#
  SELECT name, price FROM pizza
  WHERE price < 15 AND vegan = true;
#]]

25. Line Comment

Hash comments out the rest of the line. Lives outside elements, like a script header.

cx# weekend special — pulled Monday
[pizza name=TruffleSpecial price=24]

26. Inline Block Comment

Element-shaped — fits inside brackets where hash cannot reach.

cx[pizza name=Diavola [- TODO confirm price ] price=14]

27. Multi-Line Block Comment

Canonical for multi-line notes.

cx[-
  Pricing review:
    - Diavola: bump to 16?
    - Hawaiian: hold at 14
]

28. When to Use Which

Hash for line-scoped headers; when the comment must nest inside an element or span lines. Not HTMLs less-than-bang form — CX has its own.

cx# top-of-file header
[shop [- inline aside on this branch ] port=8080]

29. Nesting

Brackets inside brackets.

cx[pizza name=Margherita [base tomato]]

30. Siblings

Same shape, side by side. No separators required.

cx[pizza [topping cheese] [topping basil] [topping oil]]

31. Inline Prose With Markup

Prose and tags interleave freely. The same shapes you would write in HTML.

cx[note Try the [b Margherita] — our [em best seller], hand-tossed [strong daily].]

32. A Whole Article — Prose and Data

Headings, paragraphs, links, emphasis — CX handles document text as cleanly as XML.

cx[article
  [h1 Pepes Story]
  [p Founded in [em 1987]. See the [a href=/menu menu].]
  [p Still [strong hand-tossing] every pie.]]

33. Deeper Nesting — Children With Their Own Data

Each child carries its own attributes.

cx[pizza name=Quattro
  [topping cheese price=2]
  [topping ham    price=3]
  [topping olives price=2]]

34. Multiple Top-Level Elements (No Required Root)

A document can be a flat list.

cx[pizza name=Margherita]
[pizza name=Hawaiian]
[pizza name=Diavola]

35. Multi-Document File

One file, several independent documents. Same separator as YAML — three dashes on a line by themselves between documents.

shellcat file.cx
# [menu [pizza name=Margherita]]
# (three dashes)
# [menu [pizza name=Hawaiian]]

36. Sequence — Flat List

Reads: attribute toppings, value is the sequence of three strings.

cx[pizza toppings=(cheese, basil, oil)]

37. Array [a, b, c] — Nested List

Arrays preserve structure; sequences flatten. Use arrays when nesting matters.

cx[grid cells=[1, 2, 3]]

38. Nested Arrays

A matrix is just an array of arrays.

cx[board cells=[[1, 0, 1],
              [0, 1, 0],
              [1, 0, 1]]]

39. Map — Named Key to Value

Reads: attribute prices, value is a map with three entries.

cx[pizza prices={small: 9, medium: 12, large: 15}]

40. Collections in Body Position

Sequences, arrays, and maps can sit inside an element body too.

cx[favorites
  (Margherita, Hawaiian, Diavola)]

41. Mixed-Shape Composition

Map of sequences, multi-line. Compose freely.

cx[stats {
  monday: (12, 8, 14),
  tuesday: (10, 9, 11),
  wednesday: (15, 11, 18)
}]

42. Explicit Type Annotation

Colon-type after the name pins the bodys type, overriding auto-typing.

cx[count :int 42]
[ratio :decimal 3.14159]

43. Typed Array as Body

Colon-int-brackets for typed; colon-brackets for inferred (string array here).

cx[oven-temps :int[] 220 240 260 480]
[tags :[] cheap fast tasty]

44. Plain Table — Header Plus Rows

The colon-table form declares column names in brackets. Each line below is a row.

cx[menu :table[name size price]
  Margherita medium 12
  Hawaiian   large  14
  Diavola    medium 13
]

45. Typed Columns

Each column can carry a colon-type. Cells parse accordingly.

cx[orders :table[item:string qty:int paid:bool when:date]
  Margherita 2 true  2026-05-09
  Hawaiian   1 false 2026-05-09
]

46. Quoted Cells and Nulls

Quote cells with spaces. null is a real null in the cell.

cx[shifts :table[cook hours:int notes]
  Pepe       8 morning
  Maria      6 'closing crew'
  'Jean-Luc' 4 null
]

47. Anchor and Alias

Ampersand-classic names this element; bracket-asterisk-classic drops a full copy in.

cx[pizza &classic name=Margherita price=12 [base tomato]]
[menu [*classic] [*classic]]

48. Merge With Overrides

Asterisk-classic inherits the anchors attrs and children; overrides apply on top.

cx[pizza &classic name=Margherita price=12 [base tomato]]
[pizza *classic name=ClassicXL size=large price=16]

49. A Recipe — Prose, Data, Table, All Together

Tabular ingredients, prose steps with inline markup, multi-line notes — all in one document, one syntax.

cx[recipe name=Margherita serves=2
  [ingredients :table[item amount:string]
    flour      300g
    water      200ml
    yeast      2g
    'San Marzano tomato' 150g
    mozzarella 120g
    basil      'a handful']
  [steps
    [step Mix the dough and rest [em 24 hours] cold.]
    [step Stretch by hand — no rolling pin.]
    [step Bake at [strong 480 degrees] for 90 seconds.]]
  [notes A wetter dough gives a softer cornicione. Do not skip the cold rest.]]

50. The Whole Shop

XML decl, anchor, sigil flags, line comment, block comment, typed table, merged child, map and sequence attribute values, triple-quoted text. One syntax, everywhere.

cx[?xml version=1.0 encoding=UTF-8]
[shop &flagship name='Pepes' port=8080 +open
  # opening hours
  [hours mon-fri=11-22 sat=12-23 sun=closed]
  [- menu reviewed 2026-05-01 ]
  [menu :table[name:string size price:decimal vegan:bool]
    Margherita medium 12.00 true
    Hawaiian   large  14.00 false
    Diavola    medium 13.00 false]
  [staff [cook &lead name=Pepe shift=morning +founder]
         [cook *lead name=Maria shift=closing -founder]]
  [contact
    address='123 Forno Lane'
    coords={lat: 40.8518, lon: 14.2681}
    phones=('+39 555 0101', '+39 555 0102')]
  [tagline Hand-tossed since 1987. Still tossing.]]

The Arc

Bare attribute then element then strings then text bodies then comments then structure then collections then typed arrays then tables then anchors then the whole shop. Every step adds one shape; no shape requires anything the earlier ones do not already give you.
