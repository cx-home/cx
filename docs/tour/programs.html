    50 Ways to Love Your CXL Code

    Fifty CXL directives, simple to complex. Pizzeria edition.

    Read This First

    Fifty short CXL examples — interpolation, paths, filters, conditionals, iteration, functions, modules — that walk from the simplest substitution to a full pipeline with module activation, HTML-safe escaping, function definition, structured logging, semantic merge, and iteration. Each example pairs a tiny data input with a directive snippet.

    1. A Literal Value

    evaluates and prints. Here, the number 42.

    cx[?=42]

    2. A Literal String

    Same form; strings and numbers interpolate identically.

    cx[?='Hand-tossed since 1987']

    3. Read an Attribute — @name

    @name is CXPath for the attribute named name. Prints Margherita.

    cx[pizza name=Margherita]
[?=@name]

    4. Find Anywhere — //

    // matches a pizza element at any depth.

    cx[order [pizza name=Margherita]]
[?=//pizza/@name]

    5. Inside Body Text

    A directive sits inside text. The rest stays as written.

    cx[pizza name=Margherita]
[receipt Thanks for ordering [?=@name]!]

    6. Inside an Attribute Value

    Interpolation works in attributes and in text. One mechanism, two positions.

    cx[user id=42 name=Joe]
[a href=/u/[?=@id]/profile View [?=@name]s profile]

    7. Several on One Line

    Each is independent.

    cx[pizza name=Margherita price=12]
[line [?=@name] — [?=@price]€]

    8. Inside a Generated Element

    Per iteration, build a fully-formed … element.

    cx[catalog [c cid=42 name=Joe] [c cid=43 name=Ann]]
[?for c :in //c :return [a href=/u/[?=c/@cid] [?=c/@name]]]

    9. Child Step

    Child steps separated by /. Prints Margherita.

    cx[shop [menu [pizza name=Margherita]]]
[?=//shop/menu/pizza/@name]

    10. Parent Axis — parent::*

    Walks up one element. Prints New Haven.

    cx[shop name='New Haven' [pizza name=Margherita]]
[?=//pizza/parent::*/@name]

    11. Ancestor Axis

    All ancestors of c. Prints mid;top;

    cx[a tag=top [b tag=mid [c found]]]
[?for x :in //c/ancestor::* :return [?=x/@tag];]

    12. Following-Sibling Axis

    Walks siblings to the right of the matched node.

    cx[row [cell n=1] [cell n=2] [cell n=3]]
[?for x :in //cell[@n=1]/following-sibling::* :return [?=x/@n];]

    13. Predicate Filter — [@attr=value]

    Brackets inside CXPath are predicates, not new elements.

    cx[menu [pizza name=Margherita] [pizza name=Hawaiian]]
[?=//pizza[@name='Hawaiian']/@name]

    14. Upper-Case

    Wrap a value with to call a filter.

    cx[pizza name=margherita]
[?=[?upper [@name]]]

    15. Default — Fall Back When Missing

    Graceful fallback; no exception.

    cx[pizza name=Mystery]
[?=[?default [@price, 0]]]

    16. Composed Filters — Nested

    Inside-out: trim, then upper.

    cx[pizza name='  margherita  ']
[?=[?upper [[?trim [@name]]]]]

    17. String Length

    Counts characters. Prints 10.

    cx[pizza name=Margherita]
[?=[?string-length [@name]]]

    18. Todays Date

    , , .

    cx[?=[?current-date]]

    19. Pipeline |> — Left-to-Right Composition

    Same result as composed filters, read top-down instead of inside-out.

    cx[pizza name='  margherita  ']
[?=@name |> trim |> upper]

    20. Arrow => — Method-Call Style

    XQuerys invocation syntax. Reads as name.lower().

    cx[pizza name=MARGHERITA]
[?=@name => lower()]

    21. String Concatenation ||

    Join strings with double-pipe, like SQL.

    cx[user first=Ada last=Lovelace]
[?=@first || ' ' || @last]

    22. Range — M to N

    Inclusive range. Prints 1;2;3;4;

    cx[?for n :in 1 to 4 :return [?=n];]

    23. If — Positional Form

    Three slots: condition, then, else.

    cx[pizza stock=0]
[?if [@stock > 0, in stock, out of stock]]

    24. If — Labeled Form

    Same semantics, named slots — usually clearer.

    cx[pizza stock=5]
[?if @stock > 0 :then in stock :else out of stock]

    25. Skip the Else Branch

    False condition renders nothing.

    cx[pizza featured=true]
[?if @featured :then ★ featured!]

    26. Existence Check

    A node-set is truthy when non-empty.

    cx[pizza [tags vegan]]
[?if [//tags, yes, no]]

    27. Multi-Branch — No Else-If Ladder

    Each is a branch; * is the catch-all.

    cx[pizza stock=2]
[?if [[@stock > 100, plenty], [@stock > 10, some], [@stock > 0, last few], [*, sold out]]]

    28. For — Positional Form

    Slots: variable, source, body.

    cx[pizza [topping cheese] [topping basil] [topping oil]]
[?for [t, //topping, [?=t/@name];]]

    29. For — Labeled Form

    Same semantics with :in and :return.

    cx[pizza [topping cheese] [topping basil] [topping oil]]
[?for t :in //topping :return [?=t/@name];]

    30. Range Loop — Generate Elements

    Produces .

    cx[?for n :in 1 to 3 :return [slot id=[?=n]]]

    31. Nested For

    Loop over pizzas; inside, loop over each pizzas toppings.

    cx[shop [pizza name=Margherita [topping cheese] [topping basil]]]
[?for p :in //pizza :return
  [grp [?=p/@name]: [?for t :in p/topping :return [?=t/@name],]]]

    32. With — Positional

    Inside with, @owner and @region refer to meta. Prints Pepe / IT.

    cx[shop [meta owner=Pepe region=IT]]
[?with [//meta, [?=@owner] / [?=@region]]]

    33. With — Labeled

    Named-slot variant.

    cx[shop [meta owner=Pepe region=IT]]
[?with //meta :return [?=@owner]/[?=@region]]

    34. Let — Bind Once, Reuse

    Compute tax once, use it where the binding is in scope.

    cx[pizza price=12]
[?let tax :be @price * 0.22 :return Total: [?=@price + tax]€]

    35. Let — Bind a Pipeline Result

    Pipelines and let-bindings compose naturally.

    cx[pizza name='  margherita  ']
[?let clean :be @name |> trim |> upper :return Welcome, [?=clean]!]

    36. Define a Template Fragment

    The body runs in the calling context.

    cx[?def greet :body Hello [?=@name]!]
[pizza name=Pepe]
[?use greet]

    37. With One Parameter

    Once defined, the function is callable as .

    cx[?def shout :params [x] :body LOUD: [?=x]!]
[?shout 'pizza ready']

    38. Multiple Parameters

    Positional params; prints cheese / basil.

    cx[?def pair :params [a, b] :body [?=a] / [?=b]]
[?pair 'cheese' 'basil']

    39. Function Plus Iteration

    A reusable per-item template, mapped over a node set.

    cx[?def line :params [item] :body sku=[?=item/@sku];]
[order [v sku=A] [v sku=B] [v sku=C]]
[?for x :in //v :return [?line x]]

    40. Higher-Order — [?focus] and [?apply]

    builds a function from a body (underscore is the implicit arg); invokes it.

    cx[pizza [v n=5]]
[?let dbl :be [?focus :body [?=_ * 2]]
  :return [?for x :in //v :return [?=[?apply [dbl, x/@n]]]]]

    41. HTML-Safe Output

    One directive switches the evaluator into context-aware escaping. No XSS from the menu.

    cx[pizza name='<script>alert(1)</script>']
[?cx output-target=html]
[?=@name]

    42. Plain-Text Output

    Useful for terminals and files where escaping would be noise.

    cx[?cx output-target=text]
[pizza name='<b>Margherita</b>']
[?=@name]

    43. Activate a Module

    Modules expose new directive namespaces cx: log: … once activated.

    cx[?cx use-module=cx]
[?=[?cx:canonical [[?cx:parse ['[a   x=1  ]']]]]]

    44. cx:parse — Read CX From a String

    CX reads its own syntax as data. Code is data.

    cx[?cx use-module=cx]
[?=[?cx:parse ['[pizza name=Margherita]']]]

    45. cx:serialize — Emit a Value Back to Text

    Round-trip: parse then serialize. Prints .

    cx[?cx use-module=cx]
[?=[?cx:serialize [[?cx:parse ['[a x=1 y=2]']]]]]

    46. cx:canonical — Normalize

    Whitespace and attribute order canonicalized; idempotent.

    cx[?cx use-module=cx]
[?=[?cx:canonical [[?cx:parse ['[a   x=1   y=2]']]]]]

    47. cx:hash — Content Digest

    Stable hash over the canonical form. Same input always yields the same hash, in every binding.

    cx[?cx use-module=cx]
[?=[?cx:hash [[?cx:parse ['[pizza name=Margherita]']]]]]

    48. cx:merge — Three-Policy Semantic Merge

    Two trees combined by element identity. Coupons price=10 overrides the orders.

    cx[?cx use-module=cx]
[order [pizza name=Margherita price=12]]
[coupon [pizza price=10]]
[?=[?cx:merge [//order, //coupon]]]

    49. Structured Logging

    emits a structured event. Second arg is a map of fields.

    cx[?cx use-module=log log-level=info]
[?log:info ['sale', {pizza: 'Margherita', price: 12}]]
[?log:debug ['suppressed at info level']]

    50. The Whole Kitchen

    Module activation, HTML-safe escaping, function definition, structured logging, semantic merge, iteration. Six lines; the whole arc.

    cx[?cx use-module=cx output-target=html log-level=info]
[?def line :params [p] :body [li [?=p/@name] — [?=p/@price]€]]
[order [pizza name='<b>Margherita</b>' price=12]]
[coupon [pizza price=10]]
[?log:info ['rendering receipt']]
[ul [?for p :in [?cx:merge [//order, //coupon]]/pizza :return [?line p]]]

    The Arc

    Read a value then put it in context then walk paths then filter and combine then branch then loop then factor into functions then swap output mode then reflect / hash / merge / log. Every step adds exactly one capability; data from the companion document flows through unchanged.
